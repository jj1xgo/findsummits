# ADR-SRS-065: 申請エビデンス ZIP のファイル名の日付をエクスポートした日にする

| 状態 | 採用・未実装 |
| 決定日 | 2026-10-05 |

## Context

[SRS §6.2.8](../20_SRS.md#628-申請エビデンス-zipパッケージング仕様) は、申請エビデンス ZIP のファイル名を `sota_evidence_YYYYMMDD.zip` とし、`YYYYMMDD` を `metadata.generated_at` の日付部分と定めていた（完全な仕様は HLD に委ねる）。[HLD 4.21](../30_HLD.md#421-fr-021-申請エビデンス-zip-生成) の設計で、この決め方に次の 3 つの問題があると分かった。

- 申請書 XLSX のファイル名 `sota_revision_request_YYYYMMDD.xlsx` の日付は、[HLD 4.11](../30_HLD.md#411-fr-011-申請書-xlsx-生成) の D119 で、エクスポートした日の端末の現地時刻にした。[SRS §6.2.8](../20_SRS.md#628-申請エビデンス-zipパッケージング仕様) は申請書と ZIP を、編集を終えた同じ状態から続けて出力する一組としている。ZIP だけ `generated_at` から取ると、一組の日付がずれうる。
- `generated_at` はバッチの実行時刻なので、同じバッチから編集を重ねて出力した ZIP がすべて同じ名前になり、名前でいつの状態かを見分けられない。
- [HLD 4.9](../30_HLD.md#49-fr-009-sotaリスト突合match_status-判定) で、`generated_at` は UTC で書くことにした。日本時間の 0 時から 9 時に動かしたバッチでは、日付部分が前の日になる。

HLD だけを変えると、HLD と SRS の字句が食い違ったまま残る。[開発ガイド 6.3](../03_development.md#63-変更するときの手順) は、影響する文書を同じ変更で直すことを求めている。

## Decision

1. [SRS §6.2.8](../20_SRS.md#628-申請エビデンス-zipパッケージング仕様) のファイル名の行の `YYYYMMDD` を、エクスポートした日（「申請エビデンス」ボタンを押した時点）の端末の現地時刻の年月日に改める。完全な仕様は引き続き HLD に委ねる。
2. 時刻の取り方と、ZIP のエントリの時刻との関係は、[HLD 4.21](../30_HLD.md#421-fr-021-申請エビデンス-zip-生成) の D122・D124 で定める。

## Alternatives

**(A) SRS の字句どおり `generated_at` の日付部分にする**

却下。上の 3 つの問題が残る（持ち主の判断、2026-10-05）。

**(B) `generated_at` を端末の現地時刻に直した日付にする**

却下。編集を重ねた版が同じ名前になる問題が残る（持ち主の判断、2026-10-05）。

**(C) HLD だけを変え、SRS は改訂の機会まで改訂の候補として残す**

却下。HLD と SRS の字句が食い違ったまま残る（2026-10-05 の [HLD 4.21](../30_HLD.md#421-fr-021-申請エビデンス-zip-生成) の計画レビューで指摘を受け、持ち主が判断した）。

## Consequences

- 反映先: [SRS §6.2.8](../20_SRS.md#628-申請エビデンス-zipパッケージング仕様)、[HLD 4.21](../30_HLD.md#421-fr-021-申請エビデンス-zip-生成)（D122）。
- バッチの `metadata.generated_at` の意味と書き方は変えない。
- [ST](../70_ST.md) の [FR-021](../20_SRS.md#fr-021-申請エビデンス-zip-生成) の試験に、ファイル名の日付を確かめるケースを足す（[HLD 4.21](../30_HLD.md#421-fr-021-申請エビデンス-zip-生成) の 3.21.5 の 6）。ST の改訂の機会に合わせる。
