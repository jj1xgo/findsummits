# ADR-HLD-008: HLD の「未決事項と後続」の小節を廃止し、項目を種類ごとの行き先へ移す

| 項目 | 内容 |
|---|---|
| 状態 | 検討中 |
| 決定日 | 2026-10-12 |

---

## Context

[HLD](../30_HLD.md) は、各節の最後に「未決事項と後続」の小節を置いていた（2026-10-12 の devel `5cad4a5` で 38 個、番号付きの項目が 234）。小節の名前の「後続」はどこにも定義が無く、中身には種類の違うものが混ざっていた。

- 「〜で決めた」「〜で直した」の解決済みの項目（[ADR-HLD-004](ADR-HLD-004-hld-section-boundaries-and-item-references.md) の Decision 3 と [ADR-HLD-006](ADR-HLD-006-hld-decision-selection-criteria-and-open-item-cleanup.md) の Decision 3 により、HLD の確定まで消さずに残していた）
- 本当に決まっていない問い
- 「→ LLD」のように、送り先の文書が決まっている項目
- 「ST の改訂の機会」「ADR-SRS-010 の Phase 1 着手時」のような、いつか行う作業の予約
- 決めた理由や受け入れたリスクの注記

持ち主は 2026-10-12 に、小節は Issue で管理されていれば良いものだと言い、小節を廃止して項目を種類ごとに移すことを決めた。HLD を決まった設計だけを書く文書にし、決まっていないことと残っている作業は公開の Issue で追う。

## Decision

1. **小節を廃止する**。HLD に「未決事項」で始まる見出しの小節を置かない。
2. **行き先**。項目は種類ごとに次へ移す。1 つの項目に種類が混ざるときは、部分ごとに行き先を決める。ほかの項目を指すだけの項目は、指す先と同じ行き先へまとめる。

   | 種類 | 行き先 |
   |---|---|
   | 解決済み（「〜で決めた」「〜で直した」） | 消す。参照は決めた節（多くは設計判断）へ付け替える |
   | 未決の問い（「保留」を含む） | 1 項目 1 件の Issue（`type:設計` か `type:調査`） |
   | 作業の予約 | 作業の機会ごとに 1 件の Issue（`type:改善`） |
   | 送り先の文書が決まっていて、問いが残っていないもの | その節の「目的と範囲」の「対象外」の行に、送り先の文書と一緒に書く |
   | 注記（決めた理由、受け入れたリスク、確かめた事実） | 関係する本文の箇所 |

   各 NFR 節の「実測の計画」は本文なので残す。実測して評価するだけの項目は、実測の計画の該当の項目に中身を書き込んで消す（測った後に手当てを決めることは DEC178 で決めてある）。「実測してから決める」問いは Issue にする。
3. **Issue へのリンク**。Issue に移した項目は、HLD の関係する本文（無ければ節の「目的と範囲」）から `[#N](Issue の URL)「題」で決める`（作業の予約は `で行う`）とリンクする。もとの参照があればその参照も同じ形に替える。Issue を閉じるときは、決定を ADR か HLD に記録し、HLD の該当箇所を決まった内容に直す。
4. **既存の決定の置き換え**。ADR-HLD-006 の Decision 3（最終周回の最後に解決済みの項目を消して番号を振り直す）と、ADR-HLD-004 の Decision 3 のうち未決事項の部分（解決しても消さない、番号を振り直さない）を、本 ADR で置き換える。「処理の流れ」の項目を番号と題で指す書き方と検査G は変えない。
5. **過去の記録のリンク**。ADR と調査資料の本文は過去の記録なので書き換えない。消える小節を指す相対リンクだけは、リンク先を小節を消す前の commit `5cad4a5` の HLD を指す URL に替える。リンク文字列と本文は変えない。
6. **ステークホルダーの関心事**。[HLD 2.11](../30_HLD.md#211-ステークホルダー関心事ビュー) の関心事「未決事項」の答えを、各節の本文から Issue へのリンクに改める（[ADR-HLD-003](ADR-HLD-003-stakeholders-concerns-and-views-section.md) の追記）。
7. **lint**。`tools/lint_docs.py` の検査G の対象から小節を外す。HLD に「未決事項」で始まる見出しが現れたら、検査I で止める。検査I は節の番号の有無によらず見出しを見て、コードブロックの中は見ない。

## Alternatives

- 作業の予約を `todo.md` に移す: 個人運用の非公開のリポジトリにあるので、公開の HLD から指せない。却下。
- 小節を残し、解決済みの項目だけを消す: 名前の意味のはっきりしない小節と、種類の混ざった中身が残る。却下。
- HLD から Issue を指さず、Issue の側から HLD を指す: HLD の読者に決まっていないことが見えなくなり、項目を指していた約 310 本の参照を 1 本ずつ書き換えるか消す判断が増える。却下。

## Consequences

- HLD 全体の最終周回で解決済みの項目を消す作業（ADR-HLD-006 の Decision 3）は無くなる。最終周回の範囲は、本 ADR の後に決め直す。
- 新しく立てた Issue の一覧と、各項目の行き先は、下の付録にある。
