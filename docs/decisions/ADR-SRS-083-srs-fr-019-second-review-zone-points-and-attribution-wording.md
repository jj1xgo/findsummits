# ADR-SRS-083: SRS の FR-019 の 2 回目の見直しで、AZ の `points` の用途の説明と、地図帰属表示の理由の字句を直す

| 項目 | 内容 |
|---|---|
| 状態 | 採用・実装済み |
| 決定日 | 2026-10-13 |

---

## Context

2026-10-13 に、[ADR-SRS-082](ADR-SRS-082-srs-fr-019-viewer-colors-key-col-jump-and-wording-review.md) で直したソフトウェア要件仕様書（SRS）の §4.6（[FR-013](../20_SRS.md#fr-013-html-ビューア生成)）と §4.7 の [FR-019](../20_SRS.md#fr-019-html-ビューア機能仕様) を、改訂した多視点のレビュー（spec-panel）で 2 回目として見直した（[#204](https://github.com/jj1xgo/findsummits/issues/204)）。ADR-SRS-082 の直しは新しい食い違いを生んでいなかったが、次の 2 つが見つかった。

1. [FR-009](../20_SRS.md#fr-009-sotaリスト突合match_status-判定) の「Polygon: アクティベーションゾーン」の `points` を「対応ピークの `points` と同値（ビューアでの色付け用）」と説明していた。[FR-019](../20_SRS.md#fr-019-html-ビューア機能仕様) はアクティベーションゾーン（AZ）を半透明の塗りで表示するとだけ定め、色を `points` で決めるとは書いていない（標高バンド色はマーカーの規則）。概要設計書（HLD）の [4.19.2](../30_HLD.md#4192-処理の流れ) も AZ を一色で塗り、地理院地図向けのスタイルもゾーンの種類ごとの固定色にしている。AZ の `points` で色を付ける場所は無く、用途の説明だけが古かった。
2. [FR-019](../20_SRS.md#fr-019-html-ビューア機能仕様) の地図帰属表示が、その理由を「peak/col/summit/AZ/delete_zone 等の GeoJSON データは地理院標高タイル解析由来」と書いていた。`col` は `feature_type` の名前（`key_col`）と違い、サミットの点は既存 SOTA サミットの登録（[FR-009](../20_SRS.md#fr-009-sotaリスト突合match_status-判定) の「Point: 既存 SOTA サミット」）で、地理院標高タイルの解析から作ったものではない。

## Decision

1. [FR-009](../20_SRS.md#fr-009-sotaリスト突合match_status-判定) の AZ の `points` の説明から「（ビューアでの色付け用）」を外し、「対応ピークの `points` と同値」とする。属性は残す。
2. [FR-019](../20_SRS.md#fr-019-html-ビューア機能仕様) の地図帰属表示の理由を、解析から作ったフィーチャ（peak・key_col・AZ・delete_zone など）に絞って書く。`© 国土地理院` を基図によらず常に表示する要求は変えない。

要求の中身と範囲は変えない。

## Alternatives

- **(a) 1 で、[FR-019](../20_SRS.md#fr-019-html-ビューア機能仕様) に「AZ の塗りの色は標高バンドによらず一色」とも書く**: HLD が決めている色の扱いを SRS に上げることになるが、利用者に見える違いは小さく、[FR-019](../20_SRS.md#fr-019-html-ビューア機能仕様) の側に食い違いは無いので書かない。
- **(b) 1 を直さず、HLD の追従の注記にだけ残す**: SRS の説明が誤ったまま残るので採らない。

## Consequences

- SRS の [FR-009](../20_SRS.md#fr-009-sotaリスト突合match_status-判定) と [FR-019](../20_SRS.md#fr-019-html-ビューア機能仕様) の字句を直した。ツールの振る舞いは変わらず、HLD の追従は要らない。
- [FR-009](../20_SRS.md#fr-009-sotaリスト突合match_status-判定) は SRS の §4.5 の見直しの範囲にあるので、その範囲の判定を見直す。
