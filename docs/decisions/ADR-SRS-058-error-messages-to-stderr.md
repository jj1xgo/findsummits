# ADR-SRS-058: エラー・警告は標準エラー出力に出し、起動時の検査で止まるときはログファイルを作らない

| 状態 | 採用・未実装 |
| 決定日 | 2026-09-28 |

## Context

[NFR-007](../20_SRS.md#nfr-007-ログ出力) は、すべてのバッチ処理のログ（エラー・警告の内容と理由を含む）を
「stdout および設定可能なログディレクトリに同時出力」すると定めていた。

[HLD 2.3](../30_HLD.md#23-設定の受け渡し)・[2.5](../30_HLD.md#25-エラー処理終了コード) の設計では、次の 2 点がこの定めと合わない。

1. 利用者向けのメッセージ（`ERROR:`・`WARNING:` で始まる）を標準エラー出力とログファイルに出す。
   コマンドラインの慣習に合わせ、パイプライン制御（shell）が子の標準出力を解析するときに、メッセージが混ざらないようにするため。
2. 設定ファイルや引数の誤りは、処理を始める前の検査で終了コード 2 にし、ログファイルを作らない。
   ログディレクトリは設定ファイルから決まるため、設定を読めない・検証できない段階ではログファイルの置き場が確定していない。

## Decision

1. 処理の開始・終了、進捗、結果の要約といった通常のログは、従来どおり stdout とログディレクトリに同時に出す。
2. エラー・警告は、stdout ではなく標準エラー出力とログディレクトリに同時に出す。
3. 起動直後の設定・引数の検査で異常終了するときは、ログファイルを作らず、標準エラー出力だけに出す。

## Alternatives

**(A) エラー・警告も stdout に出す（SRS を変えない）**

却下。stdout を読むパイプライン制御の処理にメッセージが混ざり、コマンドラインの慣習（エラーは標準エラー出力）とも合わない。
起動時の検査でログファイルを作れない点は、この案でも残る。

**(B) SRS は変えず、HLD との食い違いを乖離として記録する**

却下。要求と設計が食い違ったまま残り、テストの判定基準が SRS と HLD のどちらかに割れる。

## Consequences

- [NFR-007](../20_SRS.md#nfr-007-ログ出力) の出力先の記述を改訂する。ログに含める項目、ログディレクトリの自動生成は変えない。
- 出力先の具体的な振り分けと、起動時の検査の条件は [HLD 2.3.3](../30_HLD.md#233-検証と記録)・[2.5.3](../30_HLD.md#253-利用者向けのメッセージ) で定める。
- 反映先: [SRS NFR-007](../20_SRS.md#nfr-007-ログ出力)、[HLD 2.5.3](../30_HLD.md#253-利用者向けのメッセージ)、[ST](../70_ST.md) の `ST-NFR-007-01`。
