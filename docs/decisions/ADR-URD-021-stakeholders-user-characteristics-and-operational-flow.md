# ADR-URD-021: URD §3 にステークホルダー・利用者の特性・運用の流れを置き、運用の流れは段の並びに留める

| 項目 | 内容 |
|---|---|
| 状態 | 採用・実装済み |
| 決定日 | 2026-10-08 |

---

## Context

[ADR-OPS-002](ADR-OPS-002-reference-standards-and-intended-deviations.md) は、URD を ISO/IEC/IEEE 29148:2018 の利害関係者要求仕様書（StRS）として扱うとした。StRS がステークホルダー、利用者の特性、運用の構想や運用シナリオを含むことは、2026-10-07 に規格と照らしたときの Web 検索の要約（公開の目次と二次資料）による。規格の本文でも、[SOURCES「開発プロセスの参照規格」](../../ref/SOURCES.md#開発プロセスの参照規格)の資料でも確かめていない。

改める前の URD §3 は「対象ユーザー（申請者）」と「利用シーン（定期的なサミットリスト更新申請の準備作業）」の 2 行だけで、次が無かった。

- 申請者のほかのステークホルダー。SOTA 日本支部マネージャ（申請書類を受け取り、公開用ビューアで確かめる）、国土地理院などのデータの提供元（[UR-010](../10_URD.md#ur-010)・[UR-011](../10_URD.md#ur-011) の相手）、開発・保守の担当（[UR-013](../10_URD.md#ur-013) が開発・テスト・運用時の検証を目的とする）。
- 利用者に前提とする知識と環境。
- 申請 1 回分の運用の流れ。[ST 第 2 部](../70_ST.md#4-第2部-ur単位の妥当性確認シナリオ)の `ST-UR-008-01` が、環境構築から成果物生成までを一部担っている。

[HLD 2.11](../30_HLD.md#211-ステークホルダー関心事ビュー) は、URD の改訂を待たずに設計の側のステークホルダーを挙げ、URD が挙げたら重なる人は URD を指す形に改めるとした（[ADR-HLD-003](ADR-HLD-003-stakeholders-concerns-and-views-section.md) の Decision 3）。

URD は確定済みである。URD → SRS のフェーズゲートは、ゲートの仕組みを入れる前だったので行っていない。

## Decision

1. [URD §3](../10_URD.md#3-ステークホルダー利用者運用の流れ) を「ステークホルダー・利用者・運用の流れ」とし、3.1 ステークホルダー、3.2 利用者の特性、3.3 運用の流れの 3 つの小節にする。
2. 3.1 は、申請担当者、SOTA 日本支部マネージャ、データの提供元、開発・保守の担当の 4 行の表にし、立場、主な関心事、対応する UR を書く。公開用ビューアの閲覧者は SOTA 日本支部マネージャに含め、別の行にしない。[SRS §6.2.7](../20_SRS.md#627-公開用ビューア閲覧専用静的ホスティング配信) は公開用ビューアの用途を申請先への証跡共有とし、[HLD 2.1.3](../30_HLD.md#213-外部要素と接続) が閲覧するアクターとして挙げるのも SOTA 日本支部マネージャだけだからである。作り手の側は 1 行にまとめる。設計を読む立場ごとの分け方（開発者、テスト設計者、保守者）は HLD 2.11.2 に置く。
3. 3.2 は、利用者に前提とする知識と環境を箇条で書く。既存の UR と §5・§6 から言えることだけを書き、新しい要求を足さない。
4. 3.3 は、申請 1 回分の流れを 7 段の番号付きの並びで書く。各段の細部（コマンド、引数、フェーズ）は書かず、[SRS §3.3](../20_SRS.md#33-フェーズ分割) と [README](../../README.md)（[UR-008](../10_URD.md#ur-008) の手順文書）に任せる。流れのうち、環境構築から成果物の保存までは ST 第 2 部の `ST-UR-008-01` で確かめる。公開用ビューアの公開は [FR-020](../20_SRS.md#fr-020-公開用ビューア配信) の試験で確かめ、申請書類の提出はツールの外で行う。
5. UR の文言・番号は変えず、UR も足さない。SRS の FR/NFR の「対応 UR」と ST の UR 単位のシナリオは変わらない。
6. URD → SRS のゲートの記録は無いので、決定は本 ADR に置く。SRS → HLD のゲートの記録には、URD を改めたことと UR を変えていないことを、補足として追記する。

## Alternatives

- **(b) ステークホルダーと利用者の特性だけを足し、運用の流れは ST に任せる**: `ST-UR-008-01` は検証のシナリオで、要求の側から申請の流れを示すものではない。StRS の運用の構想に当たる記述が URD に残らないため不採用（持ち主の判断、2026-10-08）。
- **(c) ステークホルダーだけを足す**: 利用者の特性が無いと、[UR-008](../10_URD.md#ur-008) の「ドキュメントに従って」の前提（誰が読む文書か）が決まらないため不採用（同上）。
- **(d) 運用の流れを、コマンドの単位まで詳しく書く**: README・SRS §3.3・HLD 2.10 と二重になり、片方だけ直す食い違いが起きやすいため不採用。
- **(e) 作り手の側を URD に入れず、HLD だけに置く**: [UR-013](../10_URD.md#ur-013) は開発・テスト・運用時の検証を目的にしていて、その要求の持ち主が URD のステークホルダーの表に出ない食い違いが残るため不採用（持ち主の判断、2026-10-08）。

## Consequences

- [URD](../10_URD.md) の §3 と目次を改めた。UR は変えていない。
- [HLD 2.11.2](../30_HLD.md#2112-ステークホルダーと関心事) の申請担当者、SOTA 日本支部マネージャ、データとサービスの提供元の行と、開発者・テスト設計者・保守者の注記を、URD 3.1 を指す形に改めた。[HLD 2.11.4](../30_HLD.md#2114-未決事項と後続) の 1 は、URD 3.1 が変わったときに照らす規則に改めた。
- URD 3.1 の関心事を HLD 2.11.2 の関心事の表と照らした。出典の明示（[UR-011](../10_URD.md#ur-011)）と、公開されたものがリリース版か開発版かの見分け（[UR-006](../10_URD.md#ur-006)）に当たる行は HLD 2.11.2 に無く、答える節を確かめてから足すこととして HLD 2.11.4 の 5 に置いた。
- [用語集「ステークホルダー」](../00_GLOSSARY.md#参照規格)の説明に URD 3.1 を足した。
- 29148 の本文で確かめていない点（StRS に書くべき項目の範囲と粒度）は、[ADR-OPS-002](ADR-OPS-002-reference-standards-and-intended-deviations.md) の Decision 4 に従い保留する。
