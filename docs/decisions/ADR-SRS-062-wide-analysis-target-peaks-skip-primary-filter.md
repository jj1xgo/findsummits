# ADR-SRS-062: 広域解析の対象ピークの行には一次フィルタを当てない

| 状態 | 採用・未実装 |
| 決定日 | 2026-10-03 |

## Context

[FR-007](../20_SRS.md#fr-007-per-mesh-csv-出力プロミネンス閾値適用) は per-mesh CSV に、プロミネンス一次フィルタ → 地理的範囲フィルタ → 対象ピーク絞り込み（広域モードのみ）の順でフィルタを当てる。
一次フィルタは、`key_col_resolved=true` の行のうちプロミネンスが一次フィルタ閾値（既定 130m）未満のものを落とし、per-mesh CSV と統合の行数を抑える。

広域解析（[FR-014](../20_SRS.md#fr-014-広域結合解析オーケストレーション)）は 2×2 max pooling で Key コルを高めに評価するので、確定したプロミネンスは実際より小さく出うる
（[ADR-SRS-004](ADR-SRS-004-level14-max-pooling-isolated-peaks.md)、[ADR-SRS-056](ADR-SRS-056-wide-analysis-prominence-underestimate-warning.md)）。
広域解析でコルが確定した対象ピークのプロミネンスが一次フィルタ閾値を下回ると、その行は一次フィルタで落ち、どのパターンの広域 per-mesh CSV にも出ない。
[FR-008](../20_SRS.md#fr-008-per-mesh-csv-統合) の統合では、通常解析の `key_col_resolved=false` の行が代表のまま残る。
[FR-022](../20_SRS.md#fr-022-コル充足判定) はそのピークを未確定として数え、N=5・6 でも同じことが繰り返されて、N=6 の後に
[FR-009](../20_SRS.md#fr-009-sotaリスト突合match_status-判定) の不備ゲート（`is_key_col_unresolved`）で処理が止まる。
利用者が Key コルを確定させる手段（陸地最高峰リストへの追加。[ADR-SRS-027](ADR-SRS-027-fr022-purification-fr023-pipeline-control.md)）は島の最高峰のためのもので、このピークには当てはまらない。

このピークは、確定したプロミネンスが最終フィルタ閾値（既定 150m）未満なので、設計では [FR-008](../20_SRS.md#fr-008-per-mesh-csv-統合) の最終フィルタで外し、過小評価の可能性を [ADR-SRS-056](ADR-SRS-056-wide-analysis-prominence-underestimate-warning.md) の警告一覧で知らせるべきものである。
起きるのは、3×3 の解析範囲に自分より高い陸地が無く、陸地が範囲の外へ続き、プロミネンスが一次フィルタ閾値の近く以下のピークに限られるが、起きると申請の工程が止まる。
[HLD 3.14](../30_HLD.md#314-fr-014-広域結合解析オーケストレーション) の計画レビュー（2026-10-03）で見つかった。

対象ピークには、もう 1 つの経路でもなる（2026-10-03 の spec-panel で見つかった）。通常解析の窓 X で確定し、プロミネンスが一次フィルタ閾値未満のピークは、X の per-mesh CSV から落ちる。
同じピークが隣の窓 Y の外周の近くにあり、その連結成分が Y の人工ボーダーに触れると、Y では `key_col_resolved=false` の行として無条件に出る（[FR-006](../20_SRS.md#fr-006-コル検出プロミネンス計算)、[FR-004](../20_SRS.md#fr-004-33メッシュ結合解析オーケストレーション) の「中心メッシュ内に限定しない」）。
[FR-008](../20_SRS.md#fr-008-per-mesh-csv-統合) に届くのは Y の未確定の行だけなので、代表は未確定になり、[FR-022](../20_SRS.md#fr-022-コル充足判定) が対象ピークに数える。
この経路は、3×3 の解析範囲に自分より高い陸地が無いことも、プロミネンスが一次フィルタ閾値に近いことも要らない。プロミネンスの小さいピークでも、窓の外周の近くにあれば起きる。
広域解析ではこのピークもコルが確定しうるが、プロミネンスが一次フィルタ閾値を下回るので、一次フィルタを当てたままだと上と同じく不備ゲートで止まる。

## Decision

1. [FR-007](../20_SRS.md#fr-007-per-mesh-csv-出力プロミネンス閾値適用) は、広域モード（[FR-014](../20_SRS.md#fr-014-広域結合解析オーケストレーション) から呼ばれたとき）では一次フィルタを当てない。
   広域モードのフィルタは地理的範囲フィルタ → 対象ピーク絞り込みとし、対象ピークの行は `key_col_resolved` とプロミネンスによらず出力する。通常モードは変えない。
2. [FR-008](../20_SRS.md#fr-008-per-mesh-csv-統合) の最終フィルタは、広域モードの代表レコードにもそのまま当てる。
   広域で確定し、プロミネンスが最終フィルタ閾値未満の代表は `merged_peak.csv` から外れる。
3. [ADR-SRS-056](ADR-SRS-056-wide-analysis-prominence-underestimate-warning.md) の警告一覧の条件から「一次フィルタ閾値以上」という下限を外す。
   代表が広域モードで `key_col_resolved=true`、プロミネンスが最終フィルタ閾値未満のため最終フィルタで除外したピークを、すべて一覧に出す。
   下限は、一次フィルタ閾値未満の行が [FR-008](../20_SRS.md#fr-008-per-mesh-csv-統合) に届かないことの帰結だった。本 ADR でその前提が消える。
   一次フィルタ閾値は最終フィルタ閾値の直前まで設定できる（[SRS 2.2.1](../20_SRS.md#221-設定可能項目)）ので、下限を残すと、実際は最終フィルタ閾値以上のピークが一覧に出ずに外れうる。

## Alternatives

**(A) 一次フィルタを残し、落ちた対象ピークを「確定・閾値未満」と分かる形で CSV に出す**

却下。新しい列か値が要り、[FR-007](../20_SRS.md#fr-007-per-mesh-csv-出力プロミネンス閾値適用)・[FR-008](../20_SRS.md#fr-008-per-mesh-csv-統合)・[FR-022](../20_SRS.md#fr-022-コル充足判定) にまたがる変更になる。
広域の per-mesh CSV は対象ピーク絞り込みで行が数件に限られ、一次フィルタで行数を抑える必要がない。

**(B) 警告ログで区別するだけにする**

却下。不備ゲートで止まることは変わらず、利用者に解決の手段がない。

**(C) 警告一覧の下限（一次フィルタ閾値以上）を残す**

却下。一次フィルタ閾値を最終フィルタ閾値に近づけた設定で、実際は最終フィルタ閾値以上のピークが一覧に出ずに外れうる。

## Consequences

- 広域解析でコルが確定したピークは、プロミネンスによらず [FR-008](../20_SRS.md#fr-008-per-mesh-csv-統合) に届き、代表として確定する。N=6 の後の不備ゲートで、確定したのに未確定として現れることはなくなる。
- 広域の per-mesh CSV には、一次フィルタ閾値未満の `key_col_resolved=true` の行が出うる。行は対象ピークの分だけで、統合の負荷はほとんど変わらない。
- 警告一覧には、広域で確定して最終フィルタで外れたピークがすべて出る。
  Context の 2 つ目の経路で対象ピークになったピークも出るので、過小評価とは関係のない、プロミネンスの小さいピーク（例: 30m）も並びうる。
  広域解析の対象ピークの件数も、その分だけ増えうる。件数は全国の通常解析を回すまで実測できない。実測で一覧や広域解析が過大になれば、件数を抑える手当て（例: 一覧の下限を最終フィルタ閾値からの幅で決める）を別に決める。
- 反映先: [SRS FR-007](../20_SRS.md#fr-007-per-mesh-csv-出力プロミネンス閾値適用)、[FR-008](../20_SRS.md#fr-008-per-mesh-csv-統合) の最終フィルタと除外一覧、
  [NFR-001](../20_SRS.md#nfr-001-精度プロミネンス判定) のプロミネンス判定、[ADR-SRS-056](ADR-SRS-056-wide-analysis-prominence-underestimate-warning.md) の補足、
  [ST](../70_ST.md) の `ST-FR-007-02`・`ST-FR-007-05`・`ST-FR-007-06`・`ST-FR-008-02`・`ST-FR-008-12`、[HLD 3.14](../30_HLD.md#314-fr-014-広域結合解析オーケストレーション)。
