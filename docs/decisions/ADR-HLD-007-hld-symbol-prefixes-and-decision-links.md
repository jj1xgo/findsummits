# ADR-HLD-007: HLD の記号を英語の略 3 文字にし、設計判断の参照をリンクにして付録 A を廃止する

| 項目 | 内容 |
|---|---|
| 状態 | 採用・実装済み |
| 決定日 | 2026-10-12 |

---

## Context

[HLD](../30_HLD.md) は、コンポーネント・設計判断・SRS と ADR で決定済みの前提・結合のつなぎ目を、1 文字の記号と番号で書いていた（2026-10-12 の devel で、HLD の中に `C<N>` が 1,885 回、`D<N>` が 1,654 回、`K<N>` が 67 回、`C<N>-E<n>`・`C<N>-I<n>` が 89 回）。文字の由来はどの文書にも書かれていない。メンテナは「コードで言われても意味がわからない」と言った。記号に題を添える規則（[文書管理ルール「HLD の記号の書き方」](../CLAUDE.md#hld-の記号の書き方)、2026-10-06）を入れた後も、読むには記号の早見表と付録 A を行き来する必要があった。

同じ規則の「ほかの節は、節へのリンクと D の番号と題で指す」は守られていなかった。本文の設計判断の参照 1,259 回のうちリンクは 16 回で、規則を入れた後に足した約 300 回にもリンクが無い。検査F（`tools/lint_docs.py`）が題だけを照合し、リンクを見ていなかったためである。付録 A（設計判断の一覧）の役割は、リンクの無い参照から定義の場所を引く索引と、[ADR-HLD-006](ADR-HLD-006-hld-decision-selection-criteria-and-open-item-cleanup.md) の「重要」列の置き場だけになっていた。

## Decision

1. **記号の頭を英語の略 3 文字にする**。番号は変えない。

   | 旧 | 新 | 意味 |
   |---|---|---|
   | `C<N>` | `CMP<N>` | コンポーネント（component）。正本は SRS §3.2 のコンポーネント ID 列 |
   | `D<N>` | `DEC<N>` | HLD の設計判断（decision）。HLD 全体の通し番号 |
   | `K<N>` | `PRE<N>` | SRS・ADR で決定済みの前提（premise） |
   | `C<N>-E<n>`・`C<N>-I<n>` | `CMP<N>-EXT<n>`・`CMP<N>-INT<n>` | 結合のつなぎ目（external・internal） |

   コンポーネント ID の正本は SRS なので、SRS の表と、SRS・テスト方針書・システムテスト仕様書・開発ガイド・文書管理ルール・図の記号も同じ変更でそろえる。HLD だけを改めると、同じコンポーネントに名前が 2 つできる。
2. **重要の印は定義の行に置く**。ADR-HLD-006 Decision 2 の付録 A の「重要」列を、`- DEC45（題）〔NFR・境界〕: 本文` の `〔〕` に移す。基準（ADR-HLD-006 Decision 1）は変えない。
3. **設計判断の参照はリンクにする**。`[DEC45](#444-設計判断)「題」` と書き、リンク先は定義を含む「設計判断」の小節にする。同じ節の中からの参照も同じ形にする。検査F がリンク先・題・印を照合する。新しい検査H が、`docs/` の文書と ADR と `ref/SOURCES.md` に残る 1 文字の記号を止める（調査資料とコード表記は対象外。結合のつなぎ目の ID はコード表記の中も見る）。
4. **付録 A を廃止する**。参照から定義のある小節へ直接飛べるので、索引は要らない。
5. **ADR の本文も書き換える**。[ADR-HLD-002](ADR-HLD-002-hld-chapter-order-program-structure-first.md) と [ADR-HLD-004](ADR-HLD-004-hld-section-boundaries-and-item-references.md) の Decision 4（決める前に始めた記録は直さない）の例外として、記号の改名に限り、ADR の本文の記号を新しい記号に直し、末尾に「追記: 記号の改名」の節を付ける。調査資料（`docs/decisions/research/`）、レビューの記録、Issue は直さない。

## Alternatives

- 日本語 2 文字（部品・判断・前提）: メンテナが英語の略を選んだ。
- カタカナの略: 漢字や英語の略より読みにくい。
- 記号をやめ、名前と題だけで書く: 番号が無いと、lint の照合と HLD の外からの参照のよりどころが無くなる。メンテナは記号を残して読める形にする方を選んだ。
- 設計判断を 1 つの文書に集める（arc42 §9 の中央の節）: 各節から理由が離れ、ADR-HLD-002 を覆す。メンテナが別文書は作らないと決めた。
- 重要の印の無い設計判断（79 件）を本文の文に降格する: 1 件ずつの書き直しになる。HLD の「未決事項と後続」の小節を整理した後に改めて判断する。
- 1 件ずつの HTML の目印（`<a id>`）: lint の設定と GitHub の目印の扱いに依存する。小節へのリンクで定義のすぐ近くへ飛べる。
- CMP の改名だけを SRS の段の ADR に分ける: 1 つの改名が 2 本の ADR に割れる。動機は HLD の読みやすさなので、HLD の段に置く。

## Consequences

- [HLD](../30_HLD.md) の記号を置き換え（付録 A を除いて 3,433 件）、DEC の参照を定義の小節へのリンクにし、付録 A を消して 107 件の重要の印を定義の行の `〔〕` に移した。DEC85 の題は置き換えで 30 字を超えるので「CMP3 は陸地最高峰リストの書式を CMP5 で確かめる」に縮めた。見出しの目印が変わった 9 節（3.1〜3.8、2.9.2）へのリンクを付け替えた。
- [FR-011](../20_SRS.md#fr-011-申請書-xlsx-生成) の申請書の箇条（HLD 4.11）の表計算のセル番地をコード表記にした。
- [SRS](../20_SRS.md) の §3.2 の表ほか、`ref/SOURCES.md`、[テスト方針書](../02_test_policy.md)・[システムテスト仕様書](../70_ST.md)・[開発ガイド](../03_development.md)・[文書管理ルール](../CLAUDE.md)の記号をそろえ、文書管理ルールの「HLD の記号の書き方」を改めた。
- `tools/lint_docs.py` の検査F を DEC の定義・印・リンクの照合に改め、検査H を足した。`tools/lint_trace.py` は SRS §3.2 の `CMP<N>` を読む。
- 記号を含む ADR 27 本の本文を書き換え、追記の節を付けた（付録 A へのリンクだけを外した ADR-HLD-003 には別の追記を付けた）。
- 図（`docs/figures/` の SVG と `spec-overview.html`）の文字をそろえた。
- 調査資料、レビューの記録、Issue の旧記号は残る。読むときは Decision 1 の表で読み替える。
