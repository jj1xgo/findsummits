# ADR-SRS-056: 広域解析によるプロミネンス過小評価の明記と警告ログ

| 状態 | 採用・未実装 |
| 決定日 | 2026-09-23 |

## Context

[ADR-SRS-004](ADR-SRS-004-level14-max-pooling-isolated-peaks.md) は、広域解析の 2×2 max pooling により Key コルが実際より高く評価され、
プロミネンスが過小になることを「申請において保守的」として許容している。

一方、[UR-007](../10_URD.md#ur-007) は独立峰を漏れなく検出することを求める。広域解析でコルが確定したピークのプロミネンスが、
過小評価のために最終フィルタ閾値をわずかに下回ると、[FR-008](../20_SRS.md#fr-008-per-mesh-csv-統合) の最終フィルタで
`merged_peak.csv` から外れ、利用者が気づく手段がない。過小評価の幅は、コル付近の 2×2 画素（5m 解像度）の起伏程度で、
緩やかな鞍部では数 m 以内と見込まれるため、影響は閾値近傍の少数に限られる。

## Decision

1. 広域解析で確定したプロミネンスは過小に出うることを、[NFR-001](../20_SRS.md#nfr-001-精度プロミネンス判定) に既知の限界として明記する。
2. [FR-008](../20_SRS.md#fr-008-per-mesh-csv-統合) は、代表レコードが広域モード（`analysis_id` 接頭辞 `4`/`5`/`6`）で
   `key_col_resolved=true`、かつプロミネンスがプロミネンス一次フィルタ閾値以上・最終フィルタ閾値未満のために最終フィルタで除外したピークを、
   警告ログに一覧で出力する（ピーク座標・ピーク標高・コル標高・プロミネンス・`analysis_id`）。`merged_peak.csv` の内容は変えない。
3. 一覧は利用者が確認するための情報であり、ツールは一覧のピークを自動で申請候補に残さない。
   一覧のピークを申請へ加える手段（ビューアでの追加等）は本 ADR の範囲外とし、必要になった時点で別途判断する。

## Alternatives

**(A) 既知の限界の明記だけにする**

却下。閾値近傍で落ちたピークを利用者が知る手段がなく、[UR-007](../10_URD.md#ur-007) の「漏れなく」を運用で補えない。

**(B) 広域で確定したピークは一次フィルタ閾値以上なら `merged_peak.csv` に残す**

却下。後段の [FR-009](../20_SRS.md#fr-009-sotaリスト突合match_status-判定) 以降に 150m 未満の候補を持ち込み、
申請候補の意味（最終フィルタ閾値以上）が崩れる。

**(C) コル付近を元の Z15 解像度で再評価する**

却下。コル位置の再評価手順を新設する必要があり、対象が少数に限られる現状では費用が見合わない。

## Consequences

- 閾値近傍で落ちた独立峰の候補を、利用者がログで確認できる。
- `merged_peak.csv` と後段の成果物は変わらない。
- 反映先: [NFR-001](../20_SRS.md#nfr-001-精度プロミネンス判定)、[FR-008](../20_SRS.md#fr-008-per-mesh-csv-統合)、
  [ST](../70_ST.md) の `ST-FR-008-10`、[ADR-SRS-004](ADR-SRS-004-level14-max-pooling-isolated-peaks.md) の max pooling 採用理由への注記。
