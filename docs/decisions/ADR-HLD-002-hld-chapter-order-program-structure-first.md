# ADR-HLD-002: HLD の章をプログラム構造・FR 設計・NFR 設計の順にし、付随文書へ移さない

| 項目 | 内容 |
|---|---|
| 状態 | 採用・実装済み |
| 決定日 | 2026-10-05 |

---

## Context

[ADR-HLD-001](ADR-HLD-001-program-structure-chapter-and-two-tier-it.md) は、HLD（[`30_HLD.md`](../30_HLD.md)）の FR 設計の章と NFR 設計の章の後にプログラム構造の章を足した。あわせて、プログラム構造の章が全コンポーネントでそろった後に、FR/NFR ごとの章を付随文書（31 番台）へ移し、`30_HLD.md` の本体をプログラム構造にする 2 段の進め方を決めていた（ADR-HLD-001 の Decision 6）。

この並びでは、読む順が「個々の FR の処理方式 → プログラムの構造」になる。持ち主は 2026-10-05 に、読む順を「プログラムの構造 → 個々の FR の処理方式」にし、基本設計書の形に近づけると決めた。決めた時点のプログラム構造の章は、C5 の節と共通部品の節の 2 つだけだった。

## Decision

1. HLD の章を、1 用語定義、2 アーキテクチャ・横断規約、3 プログラム構造、4 FR 設計、5 NFR 設計の順にする。章の中の節の番号の付け方は変えない（3.N が C<N>、3.9 が共通部品、4.N が FR-0NN）。第 5 章は 5.N を NFR-0NN に当てる（2026-10-06 に追記。決めた時点では第 5 章に節が無く、付け方を決めていなかった）。
2. この並びを最終形とする。ADR-HLD-001 の Decision 6（FR/NFR ごとの章を付随文書へ移す）は行わず、HLD は 1 つのファイル `30_HLD.md` のままにする。
3. `tools/lint_trace.py` は、第 3 章の宣言を、FR/NFR を「対応 SRS」に持つ節があるかの検査（T3）に数えない（ADR-HLD-001 の Decision 5 の本文も、この番号に直した）。LLD の T3 の対象（第 3 章〜第 5 章）は変えない。
4. 付け替える前に始めた記録（レビューの周回の記録、作業の記録、Issue のコメント、調査資料の本文）は、付け替えた後に結果を書き足すときも、名前と本文の番号を直さない。進捗を追う Issue の題と本文だけは、現在の状態を示すものなので新しい番号に直す。どちらに当たるかは、その記録が過去の 1 回の出来事（1 回の周回、1 件のコメント、1 つの作業）を残すものか、現在の状態を示すものかで決める。調査資料の中の HLD へのリンクは、リンク先を保つために付け替えた後の節へ直し、本文の番号が付け替える前のものである旨を注記する。ADR の本文のリンクと表記は、過去の出来事を述べる箇所も含めて新しい番号にした（冒頭の注記は ADR-HLD-001 にだけある）。付け替える前に書いた記録と照らすときは、番号の対応を次の表で引く。

| 付け替える前 | 付け替えた後 | 中身 |
|---|---|---|
| 第 3 章（3.1〜3.23。3.10 は FR-010 の削除による欠番、3.20 は付け替えた時点で未執筆） | 第 4 章（4.1〜4.23。4.10 は削除による欠番、4.20 は未執筆で、[FR-020](../20_SRS.md#fr-020-公開用ビューア配信) の節をどの章の形で書くかは [ADR-HLD-001](ADR-HLD-001-program-structure-chapter-and-two-tier-it.md) で保留） | FR 設計 |
| 第 4 章 | 第 5 章 | NFR 設計 |
| 第 5 章（5.1〜5.8、5.9。付け替えた時点で書いてあったのは 5.5 と 5.9 だけ） | 第 3 章（3.1〜3.8、3.9） | プログラム構造 |

小節も同じように付け替える（3.8.2 は 4.8.2、5.5.3 は 3.5.3）。

## Alternatives

- ADR-HLD-001 の Decision 6 のとおり、FR/NFR ごとの章を付随文書へ移す: 番号の付け替えをもう一度行い、lint を 2 つのファイルにまたがる形に直すことになる。却下。
- この並びを付随文書へ移す前段とし、後で付随文書へ移す: 番号の付け替えが 2 回になる。却下。
- 章の並びを変えない: 読む順が「個々の FR → プログラムの構造」のままになる。却下。
- ADR-HLD-001 を書き直すだけにする: Decision 6 を取り消した判断と理由が、独立した記録として残らない。却下。
- 番号を変えず、冒頭の「読み方」でプログラム構造の章から読むよう案内するだけにする: 付け替えの費用は掛からないが、章の番号の順と読む順が食い違い、基本設計書の形（構造から処理方式へ）にならない。却下（2026-10-06 に追記。決めたときに比べた記録が無かった案）。
- 番号を変えず、ファイルの中で章の置き場だけを入れ替える: 章の番号がファイルの中の並び順と合わなくなり（第 3 章の前に第 5 章が来る）、番号から位置を探せなくなる。却下（同上）。

## Consequences

- [HLD](../30_HLD.md) の章と節の番号、目次、リンクを付け替えた。ほかの文書から HLD の節へのリンクと、図の出典の表記も新しい番号にした。
- [文書管理ルール](../CLAUDE.md)の「HLD と LLD の書き分け」と「追跡の宣言」、[テスト方針書](../02_test_policy.md)の IT の対応先を、新しい章の番号に直した。
- ADR-HLD-001 の本文の章と節の番号を新しい番号に直し、Decision 6 から本 ADR を指した。ADR-HLD-001 の状態は、全コンポーネントの節がそろったときに「採用・実装済み」にする。
- 進捗を追う Issue の題と本文（現在の状態を示す記録。Decision 4）は、新しい番号に直す。
- spec-panel の手順の、記録の名前の規則に、第 3 章の節の名前の付け方（節番号の後にコンポーネントの ID を付ける）を足した。第 4 章・第 5 章の節は、付け替える前に同じ番号の記録が無いので、節番号だけにする。HLD の第 5 章の前置きに、5.N が NFR-0NN に当たることを書いた（2026-10-06 に追記）。

## 追記（2026-10-10）: 第 6 章の追加

第 5 章の後に「[6. 要求追跡マトリクス](../30_HLD.md#6-要求追跡マトリクス)」を足した（[ADR-HLD-005](ADR-HLD-005-hld-traceability-matrix-and-program-table.md)）。Decision 1 の第 1〜5 章の並びと、Decision 2 の 1 つのファイルのままにすることは変えない。
