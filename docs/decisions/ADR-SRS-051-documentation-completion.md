# ADR-SRS-051: 手順文書による環境構築・成果物生成の完遂性

| 状態 | 採用・未実装 |
| 決定日 | 2026-09-21 |

## Context

[UR-008](../10_URD.md#ur-008) はドキュメントに従って環境構築から成果物生成まで実行できることを要求する。
既存の [NFR-006](../20_SRS.md#nfr-006-可搬性環境) は動作環境、[NFR-007](../20_SRS.md#nfr-007-ログ出力) はログの性質を規定するが、
手順文書の存在・範囲・完遂条件を規定していなかった。一方、ST の既存専用シナリオは文書外の暗黙知なしでの完遂を要求していた。
[UR-011](../10_URD.md#ur-011) も README を成果物に含めており、利用者向け文書はプロダクトの要求対象である。

## Decision

[NFR-011](../20_SRS.md#nfr-011-手順文書による環境構築成果物生成の完遂性) を設け、README から辿れる手順による完遂を要求する。
既存環境・ログ要件は個別の環境品質/ログ品質として対応を維持し、新 NFR が手順全体の完遂に直接責任を持つ。
環境・ログは完遂の前提/支援でもあるが、それだけで本要求を充足したとはしない。

- SRS は文書の入口、環境構築・入力準備・バッチ実行・ブラウザ操作・成果物確認・異常時の対処の範囲と合格条件を定める。
- ST は文書検査、クリーン環境からの全国175メッシュの E2E、入力不足からの再実行、警告付き続行と停止の区別を検証する。
  文書チェックリストと成果物別の最低限の内容確認を置く。全数の精度・値の検査は対応 FR/NFR の ST に委ねる。
- [ADR-SRS-028](ADR-SRS-028-nationwide-batch-matching-fr010-removal.md) の全国一括突合と不備ゲートを維持する。
  正常な空出力を許容し、正当なゲート停止は未完了として原因を分類する。根拠を記録した規定どおりの設定見直し後は再実行できる。
- 初回はツール専用状態のない環境から始める。文書修正等の再実行では、記載手順で取得したキャッシュ等を取得履歴付きで再利用できる。
  既存作業領域や実データの削除を要求しない。既存の最終出力を今回生成したものと数えない。
- 手順の実装は README とリンク先へ集約し、対象版と一致させる。後工程の OPS 本体が未作成でも、ST 実行時点には利用者向け手順一式を揃える。
  非公開情報や未作成文書への参照で充足としない。具体的なコマンドや新しい自動復旧方式はこの決定で先取りしない。

SRS §3.1 では公開用ビューアも最終出力に含むが、本 NFR の終点は申請用成果物の生成までとする。
ホスティング配信は [FR-020](../20_SRS.md#fr-020-公開用ビューア配信) の検証で受け持ち、生成完了を公開完了と報告しない。
公式提出も本 NFR の終点には含めない。

要求の正本は上記 NFR、受入条件は [ST の NFR 節](../70_ST.md#38-非機能要件) と
[UR 専用シナリオ](../70_ST.md#st-ur-008-01-環境構築成果物生成の一気通貫) とする。
比較検討とレビュー記録は [採用時仕様案](research/documentation-completion-spec.md) に残す。

## Alternatives

| 案 | 採らない理由 |
|---|---|
| OPS ステージの成果物要件へ移し RTM に前提と注記する | 文書の置き場は整理できるが、既存 ST が検証する完遂の合格条件を SRS に残せない |
| 既存の環境 NFR に文書規定を足す | 環境上で動作することと、文書だけで操作を完遂できることを独立して追跡しにくい |

## Consequences

手順書の整備と実地確認が必要になる。全国 E2E は時間と外部データ取得を要し、文書 lint の成功は代替にならない。
版・入力・設定・ログ・成果物の証跡を残し、環境/機能/文書の不備と正当な停止を区別して判定する。
URD の要求文とテスト方針書の ST 定義は変えない。コード・実際の利用手順・実地 ST は設計確定後に追従する。
本決定は仕様反映の完了であり、利用手順の完遂を実地で確認したことを意味しない。
