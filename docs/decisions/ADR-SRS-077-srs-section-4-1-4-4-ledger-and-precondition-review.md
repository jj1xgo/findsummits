# ADR-SRS-077: SRS §4.1〜4.4 の台帳・起動前提条件・誤記の食い違いを直す

| 項目 | 内容 |
|---|---|
| 状態 | 採用・実装済み |
| 決定日 | 2026-10-12 |

---

## Context

2026-10-12 に、改訂した多視点のレビュー（spec-panel）で、ソフトウェア要件仕様書（SRS）の §4.1〜4.4（[FR-017](../20_SRS.md#fr-017-n03-行政区域前処理データ準備)・[FR-001](../20_SRS.md#fr-001-標高タイル事前取得)・[FR-023](../20_SRS.md#fr-023-解析パイプライン制御)・[FR-004](../20_SRS.md#fr-004-33メッシュ結合解析オーケストレーション)・[FR-014](../20_SRS.md#fr-014-広域結合解析オーケストレーション)・[FR-002](../20_SRS.md#fr-002-dem-階層フォールバック)・[FR-003](../20_SRS.md#fr-003-標高デコードnodata-処理)・[FR-015](../20_SRS.md#fr-015-標高地形図出力)・[FR-005](../20_SRS.md#fr-005-ピーク候補検出)・[FR-006](../20_SRS.md#fr-006-コル検出プロミネンス計算)・[FR-007](../20_SRS.md#fr-007-per-mesh-csv-出力プロミネンス閾値適用)・[FR-016](../20_SRS.md#fr-016-ピーク域ポリゴン生成)）を見直した（[#204](https://github.com/jj1xgo/findsummits/issues/204)）。照らした相手は §6〜8 の台帳と URD である。次の食い違いが見つかった。

1. [FR-017](../20_SRS.md#fr-017-n03-行政区域前処理データ準備) は、採用した N03 ZIP の版を記録し、生成を省くときに記録した版と比べて警告を出す（2026-09-23 に足した）が、この記録が入出力の表にも [§8.1](../20_SRS.md#81-内部データ一覧) にも無かった。概要設計書（HLD）は [2.10.3](../30_HLD.md#2103-フェーズのやり直し) で、この記録を出力と同じディレクトリのテキストファイルとして持つ。[FR-017](../20_SRS.md#fr-017-n03-行政区域前処理データ準備) が出力ファイル群を生成するときに消す標高タイル取得完了記録（[ADR-SRS-059](ADR-SRS-059-tile-fetch-completion-record.md)）も、[FR-017](../20_SRS.md#fr-017-n03-行政区域前処理データ準備) の入出力の表に無く、§8.1 No.17 は補足の列にだけ書いていた。兄弟の [FR-001](../20_SRS.md#fr-001-標高タイル事前取得) は、自分で消すローカルキャッシュを入力と出力の両方に載せている。
2. [FR-001](../20_SRS.md#fr-001-標高タイル事前取得) の説明に、HTTP のステータスの具体値（200・304・404）が残っていた。[文書管理ルール「SRS 機能要件（FR）記述規約」](../CLAUDE.md#srs-機能要件fr記述規約)は、HTTP のステータスの具体値を SRS に書かず HLD に委ねる。2026-09-23 の見直しは再試行の 429・503 だけを抽象の形にしていた。
3. [HLD 4.23](../30_HLD.md#423-fr-023-解析パイプライン制御) は、[FR-023](../20_SRS.md#fr-023-解析パイプライン制御) の起動前提条件に 3 つを足していた。そのうち陸地最高峰リストの書式は [ADR-SRS-073](ADR-SRS-073-align-srs-wording-with-hld-decisions.md) で SRS に引き上げたが、通しの実行とフェーズ4 の単独起動で SOTA サミットリスト CSV があること、フェーズ3 の単独起動で標高タイルの取得完了（日本全土）を確かめることは、SRS に無かった。後者は、[ADR-SRS-060](ADR-SRS-060-fr023-reads-mesh-lists-for-precondition.md) の Decision 3 が HLD で定めるとしていた。
4. [FR-023](../20_SRS.md#fr-023-解析パイプライン制御) の入力の表が、コル未確定ピーク座標リストを「必須（フェーズ3 以降）」としていた。未確定がゼロのとき [FR-022](../20_SRS.md#fr-022-コル充足判定) はリストを作らずフェーズ4 へ進み、フェーズ4 の単独起動の前提にもこのリストは無い。
5. 誤記と書き方の揺れ: [FR-016](../20_SRS.md#fr-016-ピーク域ポリゴン生成) が 3×3 の解析範囲を「約 20km 四方」と書いていた（1次メッシュは約 80km 四方なので約 240km 四方）。[FR-006](../20_SRS.md#fr-006-コル検出プロミネンス計算) が解析範囲を「東経 123° 以東」と書いていた（日本全土1次メッシュコードリストは東経 122°〜123° のメッシュ 3622 を含む）。[FR-014](../20_SRS.md#fr-014-広域結合解析オーケストレーション) の入力のデータ名が §8.1 の名称に修飾語を足した形だった。[FR-014](../20_SRS.md#fr-014-広域結合解析オーケストレーション) の異常系の 1 か所だけが「prefetch」と書いていた。[FR-007](../20_SRS.md#fr-007-per-mesh-csv-出力プロミネンス閾値適用) がフェーズ3 からも呼ばれるのに「フェーズ2 で検出した」と書いていた。[FR-016](../20_SRS.md#fr-016-ピーク域ポリゴン生成) が設定可能項目を既定値（25m）と略語で書いていた。[FR-023](../20_SRS.md#fr-023-解析パイプライン制御) が実装の手段の名前（`set -e`）を挙げていた。

## Decision

1. §8.1 に「N03 前処理の版の記録」（No.18。生成・参照とも [FR-017](../20_SRS.md#fr-017-n03-行政区域前処理データ準備)）を足し、[§8.2.1](../20_SRS.md#821-n03-前処理済みファイル詳細仕様) に詳細を置く。[FR-017](../20_SRS.md#fr-017-n03-行政区域前処理データ準備) の入力と出力の表に載せる。標高タイル取得完了記録は [FR-017](../20_SRS.md#fr-017-n03-行政区域前処理データ準備) の出力の表に「消す」ものとして載せ、§8.1 No.17 の生成 FR の列に [FR-017](../20_SRS.md#fr-017-n03-行政区域前処理データ準備)（消去）を足す。[FR-001](../20_SRS.md#fr-001-標高タイル事前取得) の振る舞いは変えない。
2. [FR-001](../20_SRS.md#fr-001-標高タイル事前取得) の HTTP のステータスの具体値を、応答の意味（変更なしを示す応答、取得に成功した応答、地理院側未整備を示す応答）に直し、具体値は [HLD 4.1](../30_HLD.md#41-fr-001-標高タイル事前取得) に委ねる。`If-Modified-Since` と `Last-Modified` は [ADR-SRS-032](ADR-SRS-032-gsi-tile-latest-date-provenance.md) が決めた取得の手段なので残す。
3. [FR-023](../20_SRS.md#fr-023-解析パイプライン制御) の起動前提条件に、通しの実行とフェーズ4 の単独起動で SOTA サミットリスト CSV があること、フェーズ3 の単独起動で標高タイルの取得完了を確かめることを足す。入力の表に SOTA サミットリスト CSV の行を足し、標高タイル取得完了記録・日本全土1次メッシュコードリスト・北方領土除外メッシュリストの必須の条件にフェーズ3 を足す。同じ前提を「フェーズ2・フェーズ4」と書いた [FR-017](../20_SRS.md#fr-017-n03-行政区域前処理データ準備) の説明と §8.1 No.17 の補足も、フェーズ2〜フェーズ4 に直す。[§7.1](../20_SRS.md#71-ユーザー入力一覧) の SOTA サミットリスト CSV の使用 FR に [FR-023](../20_SRS.md#fr-023-解析パイプライン制御) を足す。[ADR-SRS-060](ADR-SRS-060-fr023-reads-mesh-lists-for-precondition.md) の Decision 3 のうち、フェーズ3 の単独起動でタイルを検査することを HLD で定めるとした部分は、本 ADR で改める（解析に要るメッシュの範囲は、引き続き HLD で定める）。
4. [FR-023](../20_SRS.md#fr-023-解析パイプライン制御) の入力の表のコル未確定ピーク座標リストを「必須（フェーズ3 を実行するとき）」に直す。
5. 5 の誤記と揺れを直す。

要求の中身と範囲は、3 で HLD が決めた前提条件を SRS に書いたことのほかは変えない。

## Alternatives

- **(a) 1 で版の記録を出力ファイル群の一部とみなし、台帳に行を足さない**: 直す箇所は減るが、[FR-017](../20_SRS.md#fr-017-n03-行政区域前処理データ準備) が次の起動で読み戻す永続のデータが台帳から逆に引けないまま残る。
- **(b) 2 を今のままにする**: 地理院のサーバーが返す応答の意味は外部が定める形式とも読めるが、同じ FR の再試行と異常系はすでに抽象の形にしており、規約と同じ FR の中の書き方がそろわない。
- **(c) 3 を HLD の追加として残す**: HLD 4.23 はそう明記しているが、陸地最高峰リストの書式だけが SRS にある不揃いが残る。

## Consequences

- SRS の [FR-001](../20_SRS.md#fr-001-標高タイル事前取得)・[FR-006](../20_SRS.md#fr-006-コル検出プロミネンス計算)・[FR-007](../20_SRS.md#fr-007-per-mesh-csv-出力プロミネンス閾値適用)・[FR-014](../20_SRS.md#fr-014-広域結合解析オーケストレーション)・[FR-016](../20_SRS.md#fr-016-ピーク域ポリゴン生成)・[FR-017](../20_SRS.md#fr-017-n03-行政区域前処理データ準備)・[FR-023](../20_SRS.md#fr-023-解析パイプライン制御)、§7.1、§8.1、§8.2.1 を直した。ツールの振る舞いは変わらない（3 は HLD がすでに決めていた前提条件を SRS に書いたもの）。
- [ADR-SRS-060](ADR-SRS-060-fr023-reads-mesh-lists-for-precondition.md) の状態と決定日の表の直後に、Decision 3 を本 ADR で改めた旨の注を置いた（[ADR-SRS-073](ADR-SRS-073-align-srs-wording-with-hld-decisions.md) の Decision 3 と同じ形）。
- HLD の [DEC39](../30_HLD.md#414-設計判断) が定める、版の記録が無いときにタイル取得を止める振る舞いは、SRS の [FR-001](../20_SRS.md#fr-001-標高タイル事前取得) に無いまま残る。[HLD 4.23](../30_HLD.md#423-fr-023-解析パイプライン制御) の「HLD で次の 3 つを足している」の文と、「取得完了の記録の検査」の後の、[FR-023](../20_SRS.md#fr-023-解析パイプライン制御) がフェーズ2・フェーズ4 の判定に記録を使い、`--phase 3` で記録と 2 つのリストを読むことは HLD で決めたとする段落は、3 で SRS に書いた分だけ古くなる。HLD の [DEC33](../30_HLD.md#414-設計判断) の理由が SRS の HTTP 200 の書き方を引く字句も、2 の後はずれる。どれも HLD の追従の見直しで扱う。
- システムテスト仕様書（ST）の `ST-FR-023-07` は、SOTA サミットリスト CSV の欠けと、フェーズ3 の単独起動でのタイル取得完了の欠けを、まだケースに持たない。`ST-FR-023-06` が単独起動の各段のために保存する入力にも、フェーズ3 のタイル取得完了とフェーズ4 の SOTA サミットリスト CSV が無い。ST の見直しで扱う。
