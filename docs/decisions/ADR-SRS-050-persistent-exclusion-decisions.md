# ADR-SRS-050: 申請からの個別除外と判断ファイルによる再利用

| 状態 | 採用・未実装 |
| 決定日 | 2026-09-21 |

## Context

有効レコードだけを突合する現行仕様では、廃止済みの山でも地形上の条件を満たせば新設候補になる。
また、通常の追加・削除・標高バンド変更候補を担当者判断で申請から外す経路がなく、申請書だけの
手編集ではエビデンスと一致しない。[UR-015](../10_URD.md#ur-015) は判断の再利用と、ブラウザデータ消去・
別 PC への移行後にも引き継げる判断ファイルを要求する。

[ADR-SRS-049](ADR-SRS-049-unmatched-manual-delete.md) は孤立要確認を削除申請へ含める方向の判断を定義した。
本決定は通常候補を申請から外す方向を追加する。解析対象の除去や SOTA 登録の更新は行わない。

## Decision

作業用ビューアで個別除外し、localStorage に保存するとともに JSON の判断ファイルを保存・読み込みできるようにする。

- 操作単位は [ADR-SRS-045](ADR-SRS-045-summit-xlsx-row-aggregation-model.md) の1行=1サミット。
  add（new/dominant）・band_change・通常 delete が対象。no_change・review・複数登録の保留組・担当者指定 delete は対象外。
  担当者指定削除を申請から外すには既存の「要確認に戻す」を使い、「採用したが除外中」という二重判断を作らない。
- category の5分類を維持し、全フィーチャ・両一覧に application_exclusion と exclusion_note を追加する。
  前者は空文字/manual/parent_add、後者は任意の理由または関連親を示す固定文。バッチは全件空文字。
  元の category・突合結果・解析値・登録値・geometry・バッチ件数・不備ゲートは除外では変更しない。
- 除外台帳は manual の識別キー・判断時条件・理由・元の解析日時を保持する。
  既存候補のキーは正式コードとアクション、新設はピーク座標と add（種別を区別）。仮コード・名称・日時をキーにしない。
  座標は WGS84 数値完全一致であり、丸め・近傍照合・最寄りへの付け替えを行わない。
- キーに加え登録/解析値・選ばれた親・従属削除集合等の判断時条件が一致するときだけ再利用する。
  同一キーが複数の現行候補を指す場合も適用しない。未適用の記録は保持し、識別子・差異と現行の申請可否を通知する。
  新設座標が変われば新規判断を要し、旧記録は自動削除しない。従属コード集合の変化は置換関係の変化なので親 add も再確認する。
- 親 add の除外は選択済みの主ピーク関係で従属する通常 delete を保留する。子の manual を優先し、他は parent_add。
  親の解除で parent_add だけを戻す。子だけの除外は親 add を残して関係を警告する。
  matched 親の band_change 除外は子 delete へ波及しない。派生状態 parent_add は台帳に保存せず、別親選択やゾーンの重なりによる連鎖もしない。
- 世代継承を選ぶと台帳を今回へ複製し、条件一致する判断を個別再選択なしで適用する。
  担当者指定削除は申請を増やす判断なので、新世代での個別再採用を引き続き要求する。
  除外は申請対象を減らすが、必要な申請を省くリスクも残るため、継承/読込への同意と条件一致を必須にし、適用/未適用一覧・件数を示す。
- 判断 JSON は台帳全体を保存し、不在対象も含む。parent_add・解除後の理由下書き・通常編集・担当者指定削除の採用判断は含めない。
  明示読込時はファイル全体を検証し、追加/変更/削除と適用件数のプレビュー・確認後に台帳全体を一括置換する。
  自動マージ・日時による勝者選択は行わない。不正 JSON・非対応版・欠落・型不正・重複キーは全体拒否し、現在状態を保持する。
- 申請書は category が add/delete/band_change かつ application_exclusion が空文字の行だけを出力する。
  改訂一覧・5 GeoJSON は除外された行と関連フィーチャも保持し、元の分類・位置と除外理由を記録する。
  各出力と公開用は [FR-019](../20_SRS.md#fr-019-html-ビューア機能仕様) が確定した現在状態を消費し、除外を再導出しない。
- 理由未記入は警告して除外と出力を許す。理由が公開エビデンスに含まれる旨を入力欄と両申請出力ボタンに示す。
  判断 JSON はエビデンス ZIP に同梱しない。公開用には除外状態の閲覧・検索・表示切替だけを提供し、台帳管理・読込・編集は提供しない。
- 廃止履歴だけで近くの候補を自動除外しない。担当者が一度除外した同一対象・同条件の候補を抑止する。
  廃止履歴の近傍照合・表示・ルール生成、座標変更後の自動追跡、共同編集・自動マージ・サーバ保存・操作履歴監査は範囲外。

値域は [共通属性](../20_SRS.md#各フィーチャのプロパティ)、操作・関連フィーチャ・警告は
[FR-019](../20_SRS.md#fr-019-html-ビューア機能仕様)、識別・条件は [除外台帳](../20_SRS.md#823-除外台帳)、
保存・復元は [SRS §8.2.2](../20_SRS.md#822-localstorage-編集内容詳細仕様)、
ファイル契約は [出力 JSON](../20_SRS.md#6210-除外判断-json) と [読込入力](../20_SRS.md#728-除外判断ファイル) を正本とする。
受入条件は [ST](../70_ST.md)、比較検討とレビュー記録は [採用時仕様案](research/persistent-exclusion-decisions-spec.md) に残す。

## Alternatives

| 案 | 採らない理由 |
|---|---|
| localStorage だけに保存 | データ消去や別 PC への移行に対応できない |
| バッチが判断ファイルを読み候補を消す | 解析結果と申請判断を混同し、エビデンスや不備検出から対象を隠す |
| review へ分類変更・第6カテゴリ追加 | 元の提案種別を失い、解析由来の要確認と混同する。別属性で表現でき、5ファイルの契約を保てる |
| 仮コード・名称・近傍距離を永続キーにする | 再採番や座標変更時に別の対象へ誤転用する可能性がある |
| 識別キーだけ一致すれば再適用 | 解析・登録値や親子関係の変化を見落とす。条件比較を併用する |
| 毎回すべての除外を個別に再選択 | 同条件での再提案抑止を満たさない。担当者指定削除と異なり申請を減らす判断に限定し、条件検証と一覧確認を併用する |
| 子の除外で親も自動除外、matched 親の変更除外で子も保留 | 独立に判断できる申請まで除外する。追加が成立しない場合の従属削除だけを保留する |
| 重複レコードを黙って間引く・部分的に読み込む | 1キー1判断の生成契約違反や手編集異常を隠す。内容が同一でも全体拒否し、修正後の再読込を可能にする |
| 廃止履歴から既知の不採用として自動除外 | 使用カラムから廃止理由は分からず、登録座標と解析ピークの同一性も保証できない |

## Consequences

[ADR-SRS-044](ADR-SRS-044-category-property-summit-centric-5class.md) の分類を保ち、申請行選定へ除外属性を追加する。
[ADR-SRS-045](ADR-SRS-045-summit-xlsx-row-aggregation-model.md) の行集約・行数・並びは保持する。
[ADR-SRS-048](ADR-SRS-048-multiple-summits-in-one-az.md) の保留組に操作を追加せず、
[ADR-SRS-049](ADR-SRS-049-unmatched-manual-delete.md) の担当者指定削除と保存範囲・継承条件を分離する。

最初の除外は人が判断し、地形・登録条件の変化後は再確認が必要となる。条件一致でも現地の不変は保証できない。
JSON は利用者自身が保管する。ブラウザ保存に失敗しても有効なメモリ状態からファイルを保存できるが、
ダウンロード要求だけで実ディスクへの保存完了を保証しない。公開エビデンスには今回適用した理由が残る。

HLD で具体的な JSON 構造・保存キー・ファイル名・座標数値の往復表現・画面配置・容量上限時の回復操作を規定する。
本決定時点ではコード・モックアップは未実装。受入試験・ブラウザ実測・実データ確認は設計確定後に行う。
