# ADR-SRS-084: SRS の FR-011・FR-012・FR-021・FR-020 の見直しで、県名が空の追加行の警告と公開用ビューアの取得失敗を書き、出力の名前と参照をそろえる

| 項目 | 内容 |
|---|---|
| 状態 | 採用・実装済み |
| 決定日 | 2026-10-13 |

---

## Context

2026-10-13 に、改訂した多視点のレビュー（spec-panel）で、ソフトウェア要件仕様書（SRS）の §4.7 の [FR-011](../20_SRS.md#fr-011-申請書-xlsx-生成)・[FR-012](../20_SRS.md#fr-012-サミット一覧申請内容反映版生成)・[FR-021](../20_SRS.md#fr-021-申請エビデンス-zip-生成) と §4.8 の [FR-020](../20_SRS.md#fr-020-公開用ビューア配信) を見直した（[#204](https://github.com/jj1xgo/findsummits/issues/204)）。照らした相手は §6〜8 の台帳と URD である。[FR-012](../20_SRS.md#fr-012-サミット一覧申請内容反映版生成) に食い違いは無く、次の食い違いが見つかった。

1. 申請書の追加の行の B 列（県名）は、`region_name` を転記する。`region_name` は、N03 前処理済み地域 GeoJSON が無いときと、どの地域にも入らないピークで空文字になる（[FR-009](../20_SRS.md#fr-009-sotaリスト突合match_status-判定)）。このとき B 列が空欄のまま出力されるが、SRS はその扱いを書いていなかった。概要設計書（HLD）は [4.19.2](../30_HLD.md#4192-処理の流れ) の「エクスポートの前の確認」で、この場合も申請書のエクスポート時に警告すると決めていた。山岳名JP の未入力は、SRS もエクスポート時の警告を求めている（[ADR-SRS-036](ADR-SRS-036-new-peak-name-input-requirement.md)）。
2. [FR-020](../20_SRS.md#fr-020-公開用ビューア配信) の異常系に、背景タイル・地理院標高タイル・基準点タイル・ライブラリ（Leaflet）の実行時取得の失敗が無かった。同じものを取る [FR-019](../20_SRS.md#fr-019-html-ビューア機能仕様) の異常系はこれを外部境界として扱い、HLD の [4.20.3](../30_HLD.md#4203-異常系) も公開用ビューアの扱いを決めていた。入力表のライブラリの行も、ほかの FR と違い、取得失敗時の扱いを指していなかった。
3. 出力の表のデータ名が §6.1 の台帳と違っていた。[FR-021](../20_SRS.md#fr-021-申請エビデンス-zip-生成) は「申請エビデンス ZIP」（台帳は「申請エビデンス ZIP（パッケージング仕様）」）、[FR-020](../20_SRS.md#fr-020-公開用ビューア配信) は「公開用ビューア」（台帳は「公開用ビューア（閲覧専用・静的ホスティング配信）」）。§6.1 は、入出力の表のデータ名に台帳の名前を使うと定めている。
4. [FR-021](../20_SRS.md#fr-021-申請エビデンス-zip-生成) の関連フィーチャの列挙が、コルを `col` と書いていた。`feature_type` の値は `key_col` で、同じ FR の同梱ファイルの表も `key_col` と書く。
5. [FR-021](../20_SRS.md#fr-021-申請エビデンス-zip-生成) の概要が、「申請エビデンス」ボタンをビューアの生成を定める [FR-013](../20_SRS.md#fr-013-html-ビューア生成) に帰していた。ボタンを定めるのは [FR-019](../20_SRS.md#fr-019-html-ビューア機能仕様) である。出力の表の備考が、無い見出し「詳細」を指していた。
6. [FR-021](../20_SRS.md#fr-021-申請エビデンス-zip-生成) の入力「ビューア上の表示・編集状態」の備考が、使う中身（担当者指定削除と申請除外）を書いていなかった。[FR-011](../20_SRS.md#fr-011-申請書-xlsx-生成)・[FR-012](../20_SRS.md#fr-012-サミット一覧申請内容反映版生成) の同じ行は中身を挙げている。

## Decision

1. `region_name` が空文字の追加の行は、B 列を空欄のまま出力し、申請書のエクスポート時に、今回の申請対象のうち該当するピークの件数と仮サミットコード・座標を警告する。出力は止めない（山岳名JP の未入力と同じ扱い）。[FR-011](../20_SRS.md#fr-011-申請書-xlsx-生成) と、エクスポートの警告を並べる [FR-019](../20_SRS.md#fr-019-html-ビューア機能仕様) の両方に書く。
2. [FR-020](../20_SRS.md#fr-020-公開用ビューア配信) の異常系に、[FR-019](../20_SRS.md#fr-019-html-ビューア機能仕様) と同じく、実行時取得の失敗を外部境界として扱い、公開用ビューア全体は止めず、使えない機能を利用者が判別できることを書く。ライブラリの行に、取得失敗時の扱いは本 FR の異常系と書く。
3. 出力の表のデータ名を §6.1 の台帳の名前にする。
4. `col` を `key_col` にする。
5. 概要の参照を [FR-019](../20_SRS.md#fr-019-html-ビューア機能仕様) にし、備考の参照先を「説明」の同梱ファイル一覧にする。
6. 入力の備考に、使う中身を挙げる。

要求の中身と範囲は、HLD が決めていた設計からは変わらない。1 と 2 は HLD が決めていた扱いを SRS に書いたもので、ほかは名前と参照の直しである。

## Alternatives

- **(a) 1 で、B 列が空のとき警告せず、空欄のまま出力することだけを書く**: SOTA 日本支部は根拠の座標から地域を判断できるが、申請者が提出の前に気づけず、HLD の設計とも食い違う。山岳名JP の未入力と同じく、警告して続ける方を選んだ。
- **(b) 1 で、B 列が空の追加の行があるときはエクスポートを止める**: 申請の最終判断は SOTA 日本支部が行うので、ほかの未入力と同じく止めない。

## Consequences

- SRS の [FR-011](../20_SRS.md#fr-011-申請書-xlsx-生成)・[FR-019](../20_SRS.md#fr-019-html-ビューア機能仕様)・[FR-020](../20_SRS.md#fr-020-公開用ビューア配信)・[FR-021](../20_SRS.md#fr-021-申請エビデンス-zip-生成) を直した。HLD がすでに決めていた振る舞いを SRS に書いたもので、設計の振る舞いは変わらない。
- HLD の [4.19.2](../30_HLD.md#4192-処理の流れ) の警告の表の、県名が空の追加の行の警告は、SRS に裏付けができた。この警告を決めた HLD の設計判断は、SRS の改訂を促したので、HLD の重要の基準（[ADR-HLD-006](ADR-HLD-006-hld-decision-selection-criteria-and-open-item-cleanup.md)）の「上位文書」に当たるようになる。その理由は、警告が SRS の要求として書かれたことを指す形に改める。HLD の [4.20.3](../30_HLD.md#4203-異常系) の取得失敗の行は、ほかの行と同じく SRS の異常系を指す形にそろえるかを見る。どれも HLD の追従の見直しで扱う。
- システムテスト仕様書（ST）に、1 の警告と、公開用ビューアの実行時取得の失敗のケースを足すか、ST の見直しで扱う。
