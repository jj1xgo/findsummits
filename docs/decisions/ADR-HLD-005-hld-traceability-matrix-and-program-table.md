# ADR-HLD-005: HLD の末尾に要求追跡マトリクスを置き、2.2.4 をプログラムの割り当ての表として残す

| 項目 | 内容 |
|---|---|
| 状態 | 採用・実装済み |
| 決定日 | 2026-10-10 |

---

## Context

[ADR-URD-020](ADR-URD-020-requirement-traceability-and-consistency.md) は、対応関係の正を各節の追跡の宣言とし、各文書の末尾の追跡マトリクスを宣言から組み立て直して照合すると決めた。HLD の末尾の表は HLD を作るときに検査に足すことにし、Consequences に「HLD 末尾の追跡マトリクスと [§2.2.4](../30_HLD.md#224-srs-の-frnfr-との対応) の置き換えは HLD の作業で行う」と書いた。

HLD の第 2〜5 章がそろった時点（2026-10-10）で、2.2.4 には 2 つの表があった。1 つはコンポーネントごとに、そのプログラムが実現する FR と処理方式の節を並べた表で、第 3 章の各節の「対応 SRS」と一致する。HLD の冒頭の読み方、2.2.3 の図の説明、2.6 の設計判断の理由、文書管理ルールの第 3 章の宣言の規則、図の出典がこの表を指している。もう 1 つは NFR を主に負うコンポーネントの箇条で、計画者の判断で選んだもので、宣言の和とは一致しない（例: [NFR-002](../20_SRS.md#nfr-002-メモリ使用量) は 2.9 の宣言で C1〜C3 も担当に入る）。FR についても、処理方式の節の担当と第 3 章の割り当ては一致しないことがある（[FR-013](../20_SRS.md#fr-013-html-ビューア生成) は 3.6 が C6 だけ、4.13 が C6・C7・C8）。

## Decision

1. HLD の末尾（付録 A の前）に「[6. 要求追跡マトリクス](../30_HLD.md#6-要求追跡マトリクス)」を置く。行は SRS の FR/NFR（欠番を除く）、列はコンポーネント C1〜C8 と「設計の節」。
2. ✅ は、その FR/NFR を「対応 SRS」に持つ第 2・4・5 章の節の「担当コンポーネント」の和とする。「全体」の節は C1〜C8 のすべてに数える。「設計の節」は、その節を番号の順に並べる。第 3 章（プログラム構造）の節は数えない（第 3 章の宣言を被覆に数えない T3 と同じ扱い）。主に負うコンポーネントの区別は表に持たせない。
3. 2.2.4 のコンポーネントごとの FR の表は、プログラムの割り当ての表として残す。FR の列は第 3 章の各節の「対応 SRS」と、処理方式の節の列は、その FR を「対応 SRS」に持つ第 2・4・5 章の節と一致させる。NFR を主に負うコンポーネントの箇条は、§6 への案内に置き換える。その箇条に担当を足すとしていた箇所は、足す先を処理方式の節の「担当コンポーネント」の宣言にする。
4. `tools/lint_trace.py` の T4 で、§6 の表を第 2・4・5 章の宣言と、2.2.4 の FR の表を第 3 章の宣言と照合する。§6 は HLD があれば求め、2.2.4 の表は第 3 章に FR を宣言する節があれば求める。表の行は、区切りの行のほかはすべて形を検査し、節の列は HLD の中の節へのリンクだけにする。
5. HLD の章の並び（[ADR-HLD-002](ADR-HLD-002-hld-chapter-order-program-structure-first.md)）は第 1〜5 章を変えず、第 5 章の後に第 6 章を足す。ADR-HLD-002 には追記で本 ADR を指す。

## Alternatives

- 末尾には表を作らず、2.2.4 を宣言と一致する形に直して照合する: 表は 1 つで済むが、[開発ガイド §6.1](../03_development.md#61-宣言と追跡マトリクス) と ADR-URD-020 の「HLD 末尾の表」を書き直すことになり、SRS §10・ST §5 と形がそろわない。却下（持ち主の判断、2026-10-10）。
- 2.2.4 を残し、末尾の表だけを照合する: 2.2.4 の「主に負う」は判断の表で照合できず、2 つの表の中身が重なってずれる元になる。却下（持ち主の判断、2026-10-10）。
- ADR-URD-020 の字句どおり、2.2.4 を全部 §6 への案内に置き換える: 2.2.4 を指す HLD の箇所（冒頭の読み方、2.2.3、2.6、2.11 など）、文書管理ルールの第 3 章の規則、図の出典を張り替えることになる。プログラムの割り当ては第 3 章の宣言と同じ中身を一覧にする構成の図表で、§6 の ✅（処理方式の節の担当）とは意味が違うので、残して照合する方が軽い。却下（持ち主の判断、2026-10-10）。
- ✅ を主に負うコンポーネントだけにする: 宣言から組み立てられず、照合できない。却下（持ち主の判断、2026-10-10）。

## Consequences

- 宣言を直して §6 か 2.2.4 の表を直し忘れると、`make lint` と CI が止まる。表を直すときは宣言を先に直す。
- どのコンポーネントが NFR を主に負うかは、表ではなく各節の本文で読む。
- LLD の末尾の表は、LLD を作るときに検査に足す（ADR-URD-020 の Decision 3 のまま）。
