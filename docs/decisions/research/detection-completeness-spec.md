## 1. 目的と範囲

本案は2026-09-21にメンテナが採用した。
要求の正本は [NFR-001](../../20_SRS.md#nfr-001-精度プロミネンス判定)、受入手順は
[ST §3.8.2](../../70_ST.md#382-検出網羅性の基準セットと判定手順)、判断は
[ADR-SRS-052](../ADR-SRS-052-detection-completeness-acceptance.md) に反映する。本資料は採用時の検討とレビュー記録を保持する。

[UR-001](../../10_URD.md#ur-001) の全国ピーク検出と [UR-007](../../10_URD.md#ur-007) の独立峰検出について、
「網羅的」「漏れなく」を検証可能な受入条件へ具体化する。
現行の [NFR-001](../../20_SRS.md#nfr-001-精度プロミネンス判定) は閾値の適用を定めるが、
検出されなかったピークを測る基準を持たない。現行 ST は全国解析の完了件数と主要山岳のサンプル照合にとどまる。

全国の処理範囲を確認し、実行前に独立した根拠で確定した基準ピークの検出漏れ0件を必須にする方式は、メンテナ選択済みである。
これは有限の基準セットに対する合格であり、未知の全ピークに漏れがないことの数学的証明や統計的保証ではない。
URD の目標は変更せず、その達成を判断するための受入証拠と限界を明示する。
漏れを新たに発見したら欠陥として処置し、回帰基準へ追加する。

今回の対象は基準の枠組みである。基準データの全レコード作成、全国解析、照合ツールの実装は後工程で行う。
基準セットが未作成ならこの受入確認は未実施であり、仕様の採用だけで検出性能を実証したことにしない。

## 2. 方式の比較

| 案 | 評価 |
|---|---|
| 全国処理範囲の検査と、事前確定した代表的な基準ピークの検出漏れ0件 | 推奨。範囲の処理漏れと既知のピークの取りこぼしを分けて検査でき、有限の基準に対する合格を明確にできる |
| 現行 SOTA リスト全件を正解とみなし全登録との一致を要求 | 登録の座標ずれ・重複・削除対象を検出する本ツールの目的と衝突する。未登録ピークも検証できない |
| 全国全ピークの独立した正解データを整備して全件照合 | 保証範囲は広いが、正解データ自体の完全性を別途確立する大きな調査を要する。今回の枠組み整備には採らない |
| 独立した正解母集団から無作為抽出し、信頼区間で評価 | 母集団の構築と確率的な抽出設計を要し、確認済みの漏れを許容しない今回の基準とは目的が異なる。全国保証を必要とする別調査として扱う |

要件の配置は既存の [NFR-001](../../20_SRS.md#nfr-001-精度プロミネンス判定) を拡張する。
別 NFR として再現率だけを分離する案もあるが、本案は最終閾値による適格性と検出の成立を合わせて確認する品質要求なので、
現行の閾値規則を維持した上で小節を分けて追跡する。別要件を新設するかどうかで判定基準を変えない。

既存の地理院 DEM、SOTA リスト等は [SOURCES](../../../ref/SOURCES.md) の範囲で用いる。
追加のデータソースを採用する場合は、その時点で出典と用語を整備する。本案で未確認の外部ピークリストを正解にしない。

## 3. 合格条件と測定地点

### 3.1 全国処理範囲

[UR-001](../../10_URD.md#ur-001) の対象集合（採用時175メッシュ）について、期待集合と製品が使用するコード集合、
正常に処理を完了したコード集合がそれぞれ一致すること。件数だけでは合格にしない。
期待集合は [第1次地域区画の出典](../../../ref/SOURCES.md#日本の国土にかかる第1次地域区画) と URD の対象範囲から、
製品の `params/` リストや当該実行ログを写さずに導き、出典版・除外根拠とともに事前固定する。
[ADR-URD-009](../ADR-URD-009-takeshima-exclusion.md) のメッシュ5531除外と、
[ADR-URD-005](../ADR-URD-005-northern-territories-exclusion.md) のタイル単位除外は異なる粒度として適用し、
北方領土の除外を含有メッシュ全体の削除へ読み替えない。
①製品の対象リストと期待集合、②完了集合と期待集合を別々に照合し、重複・欠落を確認する。
各メッシュの完了ログと当該実行の per-mesh 成果物を対応付ける。
必要な広域解析は [FR-023](../../20_SRS.md#fr-023-解析パイプライン制御) の条件で実施し、
実行済みの段階と既存仕様が認める省略の根拠を記録する。段階の欠落を通常の早期終了と混同しない。
過去の出力だけで完了したことにしない。入力タイルの欠如や異常終了は別途記録し、対象メッシュを分母から消さない。

### 3.2 基準ピークの再現率

基準セットの全必須レコードを分母とし、§4 の条件で一意に検出できたレコードを分子とする。
合格には **検出漏れ0件、再現率100%** を要求する。全体だけでなく §5 の各必須区分について件数・漏れ数を報告する。
必須レコード0件、必須区分が空、照合条件が未確定のままでは合格にしない。
99% 等への丸め、未検出レコードの事後除外、別ピークの重複加算は許さない。

測定するのは [FR-023](../../20_SRS.md#fr-023-解析パイプライン制御) の通常/必要な広域解析と
最後の [FR-008](../../20_SRS.md#fr-008-per-mesh-csv-統合) 統合後、SOTA 突合へ渡す `merged_peak.csv` である。
範囲指定によって広域出力を除く統合を使わず、通常・広域を含む全国の最終統合結果を用いる。
一時的な per-mesh 検出だけ、SOTA の登録コードだけ、申請書の行の有無では合格にしない。
担当者の申請除外・手動削除判断をこの検査へ適用しない。

必須ピークは、固定した入力 DEM と既存の地形処理規則の下で最終閾値150m以上であることを別途確認した対象とする。
照合した行が `key_col_resolved=true` かつ最終閾値以上であることを検出成功の条件とし、
位置があるだけの未確定候補を成功に数えない。途中で未確定候補を保持する現行仕様は変更しない。
`stability=confirmed` は成功の必須条件にしない。広域代表の `-` や陸地最高峰の `unstable` は既存仕様上許されるためである。

全国処理範囲・基準セットの妥当性・再現率の条件をすべて満たして本受入基準の合格とする。
本基準に合格しても、出力の全数精度、偽陽性、不備ゲート、申請成果物等の既存 FR/NFR/ST の判定を省略しない。

## 4. 基準セットの作成と照合

### 4.1 必須の記録

ST の基準セットには、実行前に次を確定して保存する。物理ファイル形式と照合ツールは後工程で決める。

| 記録 | 内容 |
|---|---|
| セット識別 | 版、作成/承認日、メンテナの承認、事前固定した内容のコミット ID または内容ハッシュ、対応 SRS 版、入力 DEM の取得情報と内容識別情報、期待メッシュ集合、設定（一次/最終フィルタ閾値を含む） |
| ピーク識別 | セット内で不変の ID、名称、地域、SOTA コードは存在する場合の参照情報。コードが異なるだけの同一地形は重複して数えない |
| 検出位置 | WGS84 の基準位置、出力ピーク座標の許容領域または許容座標集合、その根拠。同標高頂部や採用 DEM の解像度も考慮する |
| 期待する適格性 | ピークと Key コルの確認根拠、150m以上と判断した根拠、採用 DEM の種別/状態、対象区分、確認者 |
| 判定状態 | 必須、候補保留、対象外。保留/対象外には理由と根拠を記録する。必須セットとは分けて管理する |
| 履歴 | 追加・変更・対象外化の理由、対応した検出漏れ、再評価した入力版、承認記録 |

### 4.2 正解を独立に確かめる

SOTA リスト、既存研究で扱った著名独立峰・陸地最高峰、未登録ピーク、既知の欠陥を候補源にする。
その候補が採用 DEM と仕様の閾値に適合することを、地形図・DEM の独立確認や検証対象とは独立した計算で裏付ける。
本製品のどの版・どの実行の出力も、候補位置の当たりを付ける用途にのみ使い、
適格性・許容位置・ピーク/Key コル・150m以上という正解の根拠にしない。
現行登録されているという理由だけで150m以上とみなすこともしない。
既存の親ピーク距離の代理調査は選定の手掛かりにとどめ、真の Key コルの位置・標高を確定する正解として流用しない。
陸地最高峰の手動リストは処理入力であり、そのリストに載っていること自体を適格性の独立証拠にしない。

DEM の誤差や欠損等で適格性が確定できない候補は保留とし、必須セットへ無理に入れない。
適格性を確認済みの峰に対する製品側の解析限界（広域解析の上限でもコルを解決できない等）は保留・対象外化の理由にしない。
ただし結果を見て必須から保留に移して同じ実行を合格にしない。必要区分の代替を含め、改版と再承認を要する。
実世界の地形と DEM 上の期待結果に差がある場合も、差と根拠を残す。誤差幅を一律に仮定して対象を除外しない。

### 4.3 同一ピークの照合

各必須レコードの許容位置は、別の適格ピークを同じ山として拾わない大きさ・形に事前確定する。
一律の大きな距離半径や実行結果を見た領域拡張を使わず、座標の数値完全一致だけにも依存しない。
実際の許容値と単位・境界を含むかどうかは各レコードに必須とし、数値未確定のまま試験を始めない。

全必須レコードと最終出力行を一括照合し、各レコードに該当する行がちょうど1件で、
その行が他の必須レコードへ重複割当されない場合に一意とする。
0件は未検出、複数件や重複割当は曖昧とし、いずれも検出成功へ数えない。
曖昧な場合は基準の不備か出力の不備かを切り分けるが、解消前には合格を出さない。
近接した2峰、同標高頂部、メッシュ境界の例で誤照合・取り違えがないことも確認する。
基準外の余分な行を本再現率の分子に加えない。基準外だから偽陽性と断定することもしない。

## 5. 代表性と境界条件

実データの必須セットは以下の区分をすべて満たす。一つのレコードが複数区分を満たしてよい。
区分ごとの選定理由・件数・該当 ID を選定表に残す。件数は統計的な全国保証のサンプルサイズを意味しない。

| 区分 | 最低限の対象 |
|---|---|
| 地理的な広がり | 北海道・本州・四国・九州・それら以外の島嶼にそれぞれ1件以上 |
| 登録との独立性 | 現行 SOTA 登録のある適格ピークと、登録のない適格ピークをそれぞれ1件以上 |
| 解析窓と独立峰 | 通常解析で確定するものと、通常解析の窓外に Key コルがあり広域解析を必要とするものをそれぞれ1件以上 |
| 海面確定 | 自動で海面コルを確定する島の最高峰1件以上、および採用時の陸地最高峰リストの全対象 |
| DEM の違い | 基準ピーク画素または陸上 Key コル画素で DEM5 を採用する対象と、DEM10b フォールバックを採用する対象をそれぞれ1件以上。採用種別は下記のキャッシュ画素の証拠で確定する |
| 境界と近接 | タイル境界付近、1次メッシュ境界付近をそれぞれ1件以上。近接しているが別々に150m以上を満たす2峰を1組以上 |
| 既知の漏れ | これまでに確認して修正した検出漏れがあればすべて維持。事例がない場合だけ該当なしの根拠を残して空を許容し、空の必須区分による不合格の対象外とする。同一原因の代表化は根拠と承認を記録した改版でのみ行う |

DEM 区分の証拠は、固定した入力キャッシュの対象画素について、各候補種別のタイル ID・内容ハッシュ・
画素位置・存在/NODATA/有効値と、[FR-002](../../20_SRS.md#fr-002-dem-階層フォールバック) の優先順位に従った採用種別を記録する。
DEM5 と DEM10b の画素対応・解析グリッドも明示する。海面コルは実在画素として扱わず、ピーク画素を使う。
この区分は記録した画素での採用を意味し、山域全体が同じ DEM 種別であるとは主張しない。
製品の CSV に DEM 種別列の追加を要求せず、試験側で入力から確認する。
境界付近の定義（対象境界、距離/画素数・単位・境界の包含と根拠）は各レコードへ事前記録する。

候補例は [UR-007](../../10_URD.md#ur-007) の大山・東北の孤立峰や、
[ADR-SRS-019](../ADR-SRS-019-land-summit-highest-peak-handling.md) の陸地最高峰である。
例示は期待値の確定を意味しない。SOTA コード・位置・コル・解析段階の期待値はセット作成時に一次データで確認する。
過去の研究資料の古い件数や代理距離から、特定の広域段階で必ず確定するとは決めない。

実データで正解を固定しにくい境界は、既知の地形を作った試験入力でも確認する。
150mちょうど、直下、直上、同標高頂部、近接2峰、境界を跨ぐピーク、窓外コルによる未確定保持から広域確定を対象とする。
地形の期待値は手計算等の独立した根拠を残し、UT/IT/ST の担当は [テスト方針書](../../02_test_policy.md) に従う。
この補助確認で全国実データの基準セットや処理範囲確認を置き換えない。150m直下の不採用は既存の閾値要件の検証であり、
本再現率の分母は150m以上の必須ピークに限る。

## 6. 基準の保守

初回セットは ST 実行前にメンテナが根拠・必須区分・照合条件を確認して版を確定する。
独立性は人数や役割でなく、正解の根拠が本製品のいずれの版の出力にも由来しないことを示す記録で担保する。
一人で作成・承認する場合も根拠資料と確認過程を残す。
基準レコード・期待メッシュ集合・選定表・根拠・許容位置を含む内容一式を、試験開始前にコミット ID または内容ハッシュで固定する。
開始記録にその識別子と入力版・コード版・設定を残し、終了時に同じ内容で照合したことを確認する。承認記録と開始記録も保存する。
改版時に識別子を使い回さない。単に実行後にハッシュを作っただけのものは事前確定の証拠にしない。
DEM/SOTA 参照版や解析規則・陸地最高峰リストの変更、新たな漏れの発見、照合の曖昧さを改版のトリガーとする。
SOTA リスト更新だけで地形上の必須ピークを消さず、地形・入力・仕様上の適格性を確認する。
不変の ID と旧版を保存し、削除や領域変更には独立した根拠とメンテナ承認を残す。

合格報告は入力版・基準版と事前固定識別子・対象コード版・設定・範囲照合結果・各基準の照合先・漏れ/曖昧/未確定の内訳を含める。
基準を変更した場合は旧版での結果も残し、新版で再実行/再照合した結果を別に示す。
再照合で保存済みの出力を使う場合も、新版の事前固定と開始記録を作り、元の解析の版・入力が新版と適合することを確認する。
その開始記録には照合対象の保存済み出力の内容ハッシュも残し、照合終了時に同じ内容であることを確認する。
解析のコード・入力・設定が変わる場合は解析を再実行する。再照合による合格を、解析前から新版を固定していた試験と混同しない。
基準に正当な訂正が必要でも、前の失敗をなかったことにしない。
既知の必須ピークの漏れは本基準の不合格であり、既知欠陥の登録だけで合格に読み替えない。
リリース可否の例外判断が別にある場合も、本基準の測定値・判定はそのまま報告する。

## 7. 受入例と文書への配置

| 例 | 期待する判定 |
|---|---|
| 175件の完了ログだが1コード重複・別の1コード欠落 | 全国処理範囲が不一致で不合格 |
| 必須100件中99件を検出、1件だけ消失 | 再現率99%、漏れ1件で不合格 |
| 必須全件の位置があるが、1件のコルが未確定 | そのレコードは成功に数えず不合格 |
| 近接する2基準ピークに同じ出力行を割当 | 重複割当で不合格。別の2峰を検出したことにしない |
| 必須全件が一意に確定、広域代表の stability が `-` | stability だけを理由に不合格にしない。範囲と他条件も成立すれば合格 |
| 再現率100%だが島嶼区分に必須レコードがない | 基準セットの必須区分不足で合格にしない |
| 出力を見て許容半径を広げる、未検出を対象外へ移す | 同じ基準での合格にしない。独立根拠・改版・再承認・再評価が必要 |
| 必須全件検出だが、新しい基準外の漏れが確認された | 未知の漏れゼロを主張せず、欠陥として処置し回帰基準へ追加 |

| 反映先 | 内容 |
|---|---|

| ST 第1部 | NFR の基準セット妥当性・一意照合と再現率・失敗判定のケースを追加。セットの必須記録、選定表、照合・改版手順を定める |

SRS では [NFR-001](../../20_SRS.md#nfr-001-精度プロミネンス判定) の対応 UR/RTM に
[UR-001](../../10_URD.md#ur-001) と [UR-007](../../10_URD.md#ur-007) を追加し、[UR-002](../../10_URD.md#ur-002) は維持する。
ST の全国/独立峰の UR カバレッジ行にも同 NFR と追加ケース/シナリオを載せる。
測定経路は両シナリオから [FR-008](../../20_SRS.md#fr-008-per-mesh-csv-統合)・
[FR-014](../../20_SRS.md#fr-014-広域結合解析オーケストレーション)・[FR-022](../../20_SRS.md#fr-022-コル充足判定)・
[FR-023](../../20_SRS.md#fr-023-解析パイプライン制御) へ明示参照する。
測定の経路と直接の要求実現を区別し、既存 FR の SRS RTM 対応印を試験経路だけを理由に増やさない
（[SRS §12](../../20_SRS.md#12-要求追跡マトリクス) の直接寄与の規約による）。

URD の検出目標、既存の検出・統合・突合処理は変更しない。基準セットはテスト用であり製品への新たな必須入力にしない。
後工程では実データと独立根拠を揃えて必須区分を充足し、照合を実装・実行する。
具体的な全レコードや期待値を今回未作成であることは、HLD に渡す未実施事項として記録する。
