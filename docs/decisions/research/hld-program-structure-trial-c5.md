## 試作: C5（統合・突合）をプログラムの構造で書く

- 日付: 2026-10-05
- 位置づけ: 形を判断してもらうための試作。`docs/30_HLD.md` の正式な節ではない
- 元にしたもの: HLD 2.2.3・2.3.3・2.4.5・2.5.1・2.5.5、3.8・3.9・3.18・3.22（devel cd87de8）。現行のプロトタイプ（`scripts/merge.py` など）の分け方は手本にしていない
- 書き方の方針: 処理の中身は書き直さず、既存の節の手順番号と D 番号で指す。ここに足すのは「どのプログラムが、何を受け取り、何を返すか」という構造だけ
- プログラムと関数の名前はすべて仮（正式な名前は LLD の `LLD-<モジュール名>` と UT の ID に効くので、形が決まってから付ける）

### 1. パッケージとプログラム

C5 は 4 本のプログラムからなる（D4「C5 は FR ごとの起動口」）。どれも C3 が起動し、プログラムどうしはファイルだけでつながる（D2）。

| プログラム（仮） | FR | C3 が起動する時機 | 引数（`--config` は全部に付く） |
|---|---|---|---|
| P1 `merge_peaks` | [FR-008](../../20_SRS.md#fr-008-per-mesh-csv-統合) | フェーズ2 の統合、フェーズ3 の各段の再統合。起動時の検査でも呼ぶ | `--mesh`（フェーズ2 だけ）、`--check-land-peaks`（検査のとき） |
| P2 `merge_zones` | [FR-018](../../20_SRS.md#fr-018-per-mesh-ピーク候補-geojson-統合) | P1 の直後（検査のときは呼ばない） | `--mesh`（フェーズ2 だけ） |
| P3 `check_cols` | [FR-022](../../20_SRS.md#fr-022-コル充足判定) | P2 の直後 | `--n <3〜6>` |
| P4 `match_summits` | [FR-009](../../20_SRS.md#fr-009-sotaリスト突合match_status-判定) | フェーズ4 | なし |

### 2. プログラムごとの IPO

#### P1 `merge_peaks`（[FR-008](../../20_SRS.md#fr-008-per-mesh-csv-統合)。処理の正本は 3.8.2）

- 入力
  - per-mesh CSV（C4 から。通常と広域）
  - 陸地最高峰リスト（`params/`）
  - 日本全土1次メッシュコードリスト（`params/`）
  - 北方領土除外メッシュリスト（C1 から）
  - 設定 `prominence_final_m`・`prominence_primary_m`
- 処理: 3.8.2 の 1〜7
- 出力
  - `merged_peak.csv`（P2・P3・P4・C3 へ）
  - 終了コード 0・1・2
  - 警告（対象外の名前のファイル、当たらないリストの行、広域で落としたピーク）
  - 通常のログ（件数）

#### P2 `merge_zones`（[FR-018](../../20_SRS.md#fr-018-per-mesh-ピーク候補-geojson-統合)。処理の正本は 3.18.2）

- 入力
  - `merged_peak.csv`（P1 から。6 列を使う）
  - per-mesh ピーク候補 GeoJSON（C4 から。通常だけ）
- 処理: 3.18.2 の 1〜5
- 出力
  - `merged_peak.geojson`（P4・C3 へ）
  - 終了コード 0・1・2

#### P3 `check_cols`（[FR-022](../../20_SRS.md#fr-022-コル充足判定)。処理の正本は 3.22.2）

- 入力
  - `merged_peak.csv`（P1 から。3 列を使う）
  - `--n`
- 処理: 3.22.2 の 1〜4
- 出力
  - `key_col_unresolved_peaks-<N>.csv`（C3 を経て C4 の広域へ。未確定があるときだけ）
  - 終了コード 0（ゼロ）・3（残あり）・1・2

#### P4 `match_summits`（[FR-009](../../20_SRS.md#fr-009-sotaリスト突合match_status-判定)。処理の正本は 3.9.2）

- 入力
  - `merged_peak.csv`（P1 から。13 列すべて）
  - `merged_peak.geojson`（P2 から）
  - SOTA サミットリスト CSV（利用者が配置）
  - 地域・市区町村の GeoJSON（C1 から）
  - SOTA 既存サミット GeoJSON（利用者が配置。任意）
  - 標高タイルの mtime（C2 のキャッシュ）
  - 設定 `provisional_code_max_prefix`・`unmatched_summit_threshold`・`sota_geojson_version`
- 処理: 3.9.2 の 1〜9 と「出力の組み立て」の 1〜6
- 出力
  - `merged_summit.geojson`（C6・利用者へ）
  - `merged_summit.xlsx`（利用者へ）
  - 終了コード 0・4（不備ゲート）・1・2
  - 警告（`unmatched`、複数登録、地域に入らない点など）

### 3. プログラムの中の関数（P1 だけ深く書いた例）

3.8.2 の手順 1〜7 が、そのまま関数の切れ目になる。

| 関数（仮） | 受け取るもの | 返すもの | 処理の正本 | 止める場面 |
|---|---|---|---|---|
| F1 `read_land_peaks` | 陸地最高峰リストのパス | 行の並び（名前、緯度、経度） | 3.8.2 の 1 | 無い・読めない・書式の違い（終了コード 1）。`--check-land-peaks` はこの関数だけを呼んで終わる（D85） |
| F2 `read_mesh_lists` | 2 つのリストのパス | 解析対象のメッシュコードの集合 | 3.8.2 の 1（3.4.2 の 2 と同じ） | 無い・読めない |
| F3 `select_csv_files` | `results/csv/` と `--mesh` | 読むファイルの並び（名前の昇順）と警告 | 3.8.2 の 2（D84） | 対象が 1 つも無い |
| F4 `read_rows` | ファイル 1 つ | 検査を通った行と、行ごとの Z15 の画素 (gx, gy) | 3.8.2 の 3 | 見出し・値・`analysis_id`・同じ画素の重なり |
| F5 `pick_representative` | F4 の行（1 行ずつ）、F2 の集合 | ピークの表（(gx, gy) → 代表行、`analysis_count`・`expected_count`・`stability`） | 3.8.2 の 4 | なし |
| F6 `apply_land_peaks` | ピークの表、F1 の行 | 海面確定を当てた表と警告 | 3.8.2 の 5（D80・D81・D82） | 30m 以内に 2 件以上 |
| F7 `final_filter` | ピークの表、`prominence_final_m` | 残った表と警告 | 3.8.2 の 6 | なし |
| F8 `write_merged_peak` | 残った表 | `merged_peak.csv` | 3.8.2 の 7（D83） | 書き込みの失敗 |

呼ぶ順は F1 → F2 → F3 →（ファイルごとに F4 → F5）→ F6 → F7 → F8。プログラムの中で受け渡す内部データは「ピークの表」1 つである。

P2〜P4 も同じ書き方で書ける（P4 は手順が多いので、突き合わせ・照合・採番・組み立て・書き出しの 5 群に分けることになる見込み）。試作では省いた。

### 4. 共通機能

いまの HLD では、次の処理が「3.7.2 の 5 と同じ」のような文章の参照で散らばっている。部品として 1 つにまとめられる。

#### 4.1 C5 の中の共通部品

| 部品（仮） | すること | 使うところ | 定義のある節 |
|---|---|---|---|
| U1 `read_merged_peak` | `merged_peak.csv` を読み、求められた列を検査する | P2（6 列）、P3（3 列）、P4（13 列） | 3.18.2 の 2、3.22.2 の 1（D106）、3.9.2 の 1 |
| U2 `latlon_to_z15_pixel` | 緯度経度から全球の Z15 の画素 (gx, gy) を求める | P1 の F4、P2、P4 | 3.7.2 の 5（式は用語集） |
| U3 `is_valid_coord` | 文字列が座標として読めるかを判定する | P1 の F1・F4、P3、P4 | 3.8.2 の 1 |
| U4 `great_circle_m` | 2 点の大円距離（半径 6,371,008.8m） | P1 の F6、P4（`dominant_peak_dist_m`） | 3.8.2 の 5（D80） |
| U5 `validate_zone_geojson` | ゾーンの GeoJSON の書式を検査する | P2（per-mesh）、P4（`merged_peak.geojson`） | 3.18.3、3.9.2 の 2 |
| U6 `latlon_to_mesh` | 緯度経度から 1 次メッシュコードを求める | P1 の F5（`expected_count`） | 3.7.2 の 4（D55。式は用語集） |
| U7 `parse_analysis_id` | ファイル名から解析識別子を読み、通常か広域かを見分ける | P1 の F3、P2 | 3.8.2 の 2、3.18.2 の 1 |

この表にして分かったこと: `merged_peak.csv` の検査の厚さがプログラムごとに違う（P4 は 13 列すべて、P2 は 6 列、P3 は 3 列）。P3 の 3 列は D106 で意図して決めている。U1 を「使う列を受け取る 1 つの読み手」にすれば、この違いを 1 か所で説明できる。

#### 4.2 Python のバッチ全体の共通部品（C1・C2・C5・C6 で使う）

| 部品（仮） | すること | 定義のある節 |
|---|---|---|
| G1 `load_config` | 設定ファイルを読み、自分が使うキーを検査する。誤りは終了コード 2 | 2.3.2・2.3.3 |
| G2 `log` | 通常のログ、`WARNING:`、エラーのメッセージを出す | 2.5.3（ログ形式は [NFR-007](../../20_SRS.md#nfr-007-ログ出力) の節。未作成） |
| G3 `exit_codes` | 終了コード 0〜4 の定数と返し方 | 2.5.1 |
| G4 `write_output` | 出力を書き、失敗したら後始末して終了コード 1 | 2.5.5（P3 は書きかけを消す。P4 は 2 つをそろえて置く。D101） |
| G5 `read_mesh_list` | メッシュコードのリストと `--mesh` の値を読む | 2.4.3、3.4.2 の 2 |

U2・U6 の式は C4（C++）にも要る。C++ と Python で別々に実装し、共通のテストベクトルで一致を確かめる考え方（D6）に合わせる。

### 5. 結合テスト（IT）の見え方

この形にすると、IT の対象が表から拾える。

**内部結合（C5 の中のプログラムどうし）**

| つなぎ目 | 渡すもの | 確かめること（例） |
|---|---|---|
| P1 → P2 | `merged_peak.csv` | P1 の代表行の Z15 の画素で、P2 がゾーンを選べる（D75・D76）。ゾーンの欠けで止まる（D78） |
| P1 → P3 | `merged_peak.csv` | 未確定の行が、文字列と行の順のままリストに出る（D107）。0 行で終了コード 0 |
| P1・P2 → P4 | `merged_peak.csv`・`merged_peak.geojson` | 組がそろっていれば突合が進み、食い違えば止まる（D87） |

**外部結合（C5 とほかのコンポーネント）**

| つなぎ目 | 渡すもの | 確かめること（例） |
|---|---|---|
| C4 → P1・P2 | per-mesh CSV・GeoJSON | C4 が書いた名前・列・精度を P1・P2 がそのまま読める |
| C1 → P1・P4 | 除外メッシュリスト、地域・市区町村の GeoJSON | C1 の出力の形を読める。無いときの動き |
| C3 ↔ P1〜P4 | 引数と終了コード | 0・1・2・3・4 のそれぞれで C3 が決まった動きをする（2.5.2） |
| P3 → C3 → C4（広域） | `key_col_unresolved_peaks-<N>.csv` | C4 がリストの座標から対象のピークを引ける |
| P4 → C6 | `merged_summit.geojson` | C6 がデータファイルに写せる |

### 6. 判断が要る点

1. 関数を HLD に書くなら、LLD に何を残すか（UT と IT の境目も動く）
2. テスト方針書の IT は「コンポーネント間」と定義している。内部結合を IT に入れるなら方針書の改訂が要る
3. いまの 3 章（FR ごとの処理方式）を残して構造の章を別に立てるか、3 章をプログラム単位に組み替えるか
4. `docs/CLAUDE.md` の採番と追跡の宣言（HLD の節は SRS に対応、モジュールは LLD）との折り合い
