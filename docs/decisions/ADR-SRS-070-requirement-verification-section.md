# ADR-SRS-070: SRS に検証の節を設けて要求ごとの検証方法を示し、優先度と根拠の属性は持たせない

| 項目 | 内容 |
|---|---|
| 状態 | 採用・実装済み |
| 決定日 | 2026-10-08 |

## Context

[ADR-OPS-002](ADR-OPS-002-reference-standards-and-intended-deviations.md) で、要求の文書は ISO/IEC/IEEE 29148:2018 を参照すると決めた。29148:2018 に基づくとする公開の SRS の雛形（[SOURCES「開発プロセスの参照規格」](../../ref/SOURCES.md#開発プロセスの参照規格)の二次資料）は、要求の節とは別に検証（Verification）の節を置き、検証の情報を要求と並べて示すことを勧めている。29148:2018 が要求にどの属性（優先度・検証方法・根拠など）を持たせるかは、規格の本文を持たず、確かめていない。

[SRS](../20_SRS.md) の FR/NFR は、見出しのすぐ下に「対応 UR」の宣言だけを持ち、優先度と検証方法を持たない。根拠は、本文の該当箇所から ADR へのリンクで示している。本文が参照する ADR の数は要求ごとに 0〜25 本とばらつき、要求そのものを決めた ADR とその後の細部を決めた ADR が混ざっている。検証の中身は [ST](../70_ST.md) の FR/NFR ごとのテストケースにあり、各ケースは合否判定基準を持つ。

2026-10-08 に、ADR-OPS-002 の Decision 4 に従い、属性ごとに直すか意図して保つかを決めた。

## Decision

1. **検証の節を設ける**: SRS に「13. 検証」を設け、FR/NFR ごとに検証方法と検証先を 1 行ずつ示す。テストケースは ST に置き、SRS には書かない。
2. **検証方法の言葉**: 試験・分析・検査・実演の 4 つを使う。意味と決め方（ST のテストケースの合否判定基準から決める）は[用語集「要求の検証」](../00_GLOSSARY.md#要求の検証)に置き、ほかの文書はそこを指す。要求の検証の方法として test・analysis・inspection・demonstration の 4 つを挙げる例に倣ったもので、この分類の出典と、29148:2018 の本文にこの分類があるかは確かめていない。
3. **検証先は ST にそろえる**: UT/IT で行うケースも、合否は ST に記録する（[ST §2](../70_ST.md#2-テストケース記述規約)）ので、検証先は、その FR/NFR のテストケースを持つ ST の節にする。NFR のテストケースは ST §3.8 の 1 つの表にまとまっているので、NFR の行は §3.8 を指す。
4. **優先度と根拠は持たせない**: どちらも意図して保つ形として、ADR-OPS-002 の Decision 3 の表に足す。優先度は、FR/NFR がどれも v1.0 のスコープの要求で、優先度で取捨をしないため（持たせても全部が同じ値になる）。根拠は、「対応 UR」の宣言で UR まで辿れ、ADR は決定が効く本文の箇所にリンクされているため。見出しの下に ADR を並べると本文の参照と重なり、要求を決めた ADR を選ぶ判断も検査できない。
5. **検査**: `tools/lint_trace.py` の T4 で、検証の表の各行が 3 列で 1 列目に SRS の FR/NFR の見出しへのリンク（ファイル名なし）を 1 つ持つこと、FR/NFR を過不足なく 1 行ずつ持つこと、検証方法が 4 つの言葉をこの順に重複なく「・」で並べたものであること、検証先がその FR/NFR のテストケースを持つ ST の節へのリンクだけであることを検査する（[開発ガイド §6.2](../03_development.md#62-検査)）。検証方法の値が決め方に合っているかは検査しない。

## Alternatives

- **(a) 検証方法を各 FR/NFR の見出しの下の宣言に置く**: 要求ごとに読めるが、全体を見渡せず、ST へのつながりが 33 か所に散る。二次資料の雛形の構成（要求と別の検証の節）とも違う。
- **(b) 要求追跡マトリクスに列を足す**: UR の列が 14 本あり、読めなくなる。
- **(c) 検証の節を設けず、ST を指す一文で代える**: 要求ごとの検証方法を示せない。
- **(d) 根拠を見出しの下に並べる**: 本文が参照する ADR をすべて写すと本文と重なり、要求を決めた ADR だけを選ぶと 1 本ずつの判断になって検査できない。
- **(e) 検査しない**: FR/NFR を足したときに、検証の表の直し忘れを止められない。

## Consequences

- [SRS §13](../20_SRS.md#13-検証) を設けた。
- [用語集「要求の検証」](../00_GLOSSARY.md#要求の検証)に 4 つの言葉と決め方を置いた。
- [ADR-OPS-002](ADR-OPS-002-reference-standards-and-intended-deviations.md) の Decision 3 の表に、優先度と根拠の 2 行を足した。
- [文書管理ルール「追跡の宣言」](../CLAUDE.md#追跡の宣言)と[開発ガイド §6](../03_development.md#6-要求の追跡と整合)に、検証の表の扱いと検査を足した。
- 既存の要求の内容と ST のテストケースは変えていない。
