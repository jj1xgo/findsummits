# ADR-SRS-054: SOTA サミットリストの有効判定の基準日

| 状態 | 採用・未実装 |
| 決定日 | 2026-09-23 |

## Context

[FR-009](../20_SRS.md#fr-009-sotaリスト突合match_status-判定) と [SRS §7.2.4](../20_SRS.md#724-sota-サミットリスト-csv) は、
SOTA サミットリスト CSV の `ValidTo` が「実行日以降」のレコードを現役サミットとして突合対象にしていた。

一方、[NFR-003](../20_SRS.md#nfr-003-再現性決定論的出力) は、同一ローカルキャッシュ・同一パラメータで実行したバッチ出力が
同一の内容になることを求め、例外を `metadata.generated_at` 等の実行時タイムスタンプと `metadata.software_version` に限っている。
実行日を基準にすると、同じ CSV を使っても、再実行日がある登録の `ValidTo` を越えた時点で突合対象が変わり、
match_status・category・採番が変わりうる。申請先から照会を受けて後日に再検証する場面で、この差が問題になる。

CSV の 1 行目には `SOTA Summits List (Date=DD/MM/YYYY)` 形式の基準日があり、[FR-009](../20_SRS.md#fr-009-sotaリスト突合match_status-判定) はこれを
`metadata.summitslist_date` として成果物に記録している。

## Decision

1. 有効レコードの判定基準日は、SOTA サミットリスト CSV の 1 行目の基準日（`metadata.summitslist_date`）とする。
   `ValidTo` が基準日以降のレコードを現役サミットとし、基準日より前のレコードを廃止済みとして除外する。実行日は判定に使わない。
2. 1 行目から基準日を解釈できない場合、[FR-009](../20_SRS.md#fr-009-sotaリスト突合match_status-判定) はエラー終了する（判定基準が定まらないため）。
3. 同じ CSV からは実行日によらず同じ突合対象が得られることを [NFR-003](../20_SRS.md#nfr-003-再現性決定論的出力) の再現性に含める。

## Alternatives

**(A) 実行日基準のまま、[NFR-003](../20_SRS.md#nfr-003-再現性決定論的出力) の除外条件に実行日を加える**

却下。再現性の例外を広げるだけで、後日の再検証で結果が変わる問題は残る。

**(B) 判定基準日を利用者が指定できる入力にし、成果物に記録する**

却下。入力が 1 つ増え、指定を誤る余地ができる。CSV に基準日が既にあり、それを使えば足りる。

## Consequences

- 同じ CSV を使う限り、再実行日によらず突合対象が一致する。
- CSV の基準日から実行日までの間に廃止されたサミットは、現役として扱われる。どちらの基準でも CSV が表す状態を使う点は変わらず、
  最新の状態を反映するには CSV を取り直す（[SRS §10](../20_SRS.md#10-制約前提条件) の手動差し替えと同じ運用）。
- 反映先: [SRS §7.2.4](../20_SRS.md#724-sota-サミットリスト-csv)、[FR-009](../20_SRS.md#fr-009-sotaリスト突合match_status-判定)、
  [NFR-003](../20_SRS.md#nfr-003-再現性決定論的出力)、[ST](../70_ST.md) の `ST-FR-009-22`。
