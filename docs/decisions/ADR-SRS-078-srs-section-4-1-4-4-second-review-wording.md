# ADR-SRS-078: SRS §4.1〜4.4 の 2 回目の見直しで見つけた書き方の食い違いを直す

| 項目 | 内容 |
|---|---|
| 状態 | 採用・実装済み |
| 決定日 | 2026-10-12 |

---

## Context

2026-10-12 に、[ADR-SRS-077](ADR-SRS-077-srs-section-4-1-4-4-ledger-and-precondition-review.md) で直した後のソフトウェア要件仕様書（SRS）の §4.1〜4.4 を、多視点のレビュー（spec-panel）でもう一度見直した（[#204](https://github.com/jj1xgo/findsummits/issues/204)）。ADR-SRS-077 の反映は本文に入っていて、反映で新しい矛盾が生じた箇所は無かった。次の書き方の食い違いが残っていた。

1. [FR-023](../20_SRS.md#fr-023-解析パイプライン制御) は、通しの実行の起動前提条件を、足し分（SOTA サミットリスト CSV と陸地最高峰リストの書式）だけで書き、土台が何かを書いていなかった。異常系も、起動前提条件の不足を「各段の独立起動時」に限って書いていた。概要設計書（HLD）の [4.23](../30_HLD.md#423-fr-023-解析パイプライン制御) は、通しの実行の前提を、フェーズ2 の前提に SOTA サミットリスト CSV を足したものとしている。
2. [FR-016](../20_SRS.md#fr-016-ピーク域ポリゴン生成) が、設定可能項目「プロミネンス最終フィルタ閾値」を既定値（150m）で書いていた。ADR-SRS-077 で同じ FR の「アクティベーションゾーン標高差」を名称に直したのと同じ型である。
3. [FR-017](../20_SRS.md#fr-017-n03-行政区域前処理データ準備) の「出力ファイル群」が何を指すかが書かれていなかった。ADR-SRS-077 で出力の表に版の記録と標高タイル取得完了記録を足したので、版の記録が出力ファイル群に入るかが表からは決まらなくなった。
4. [FR-017](../20_SRS.md#fr-017-n03-行政区域前処理データ準備) のフォールバックは、北方領土除外メッシュリストが無いときにエラー終了する FR を 5 つ挙げ、「読む FR は §8.1 No.16」と添えていた。No.16 の参照 FR には [ADR-SRS-073](ADR-SRS-073-align-srs-wording-with-hld-decisions.md) で [FR-016](../20_SRS.md#fr-016-ピーク域ポリゴン生成) が入ったが、[FR-016](../20_SRS.md#fr-016-ピーク域ポリゴン生成) は読み取りの失敗を呼び出し元の [FR-004](../20_SRS.md#fr-004-33メッシュ結合解析オーケストレーション) に任せていて、エラー終了する FR には入らない。
5. [FR-023](../20_SRS.md#fr-023-解析パイプライン制御) の入力の表は、1次メッシュコードリストを転送する FR のデフォルトを、まとめて「日本全土1次メッシュコードリスト」と書いていた。転送先の [FR-018](../20_SRS.md#fr-018-per-mesh-ピーク候補-geojson-統合) は、省略時に日本全土1次メッシュコードリストを使わない（ADR-SRS-073）。

## Decision

1. [FR-023](../20_SRS.md#fr-023-解析パイプライン制御) に、通しの実行の起動前提条件は、フェーズ2 の単独起動の起動前提条件に SOTA サミットリスト CSV の存在を足したものと書く。異常系は「起動時（通しの実行・各段の独立起動）」に直す。
2. [FR-016](../20_SRS.md#fr-016-ピーク域ポリゴン生成) の既定値を、設定可能項目の名称に直す。
3. [FR-017](../20_SRS.md#fr-017-n03-行政区域前処理データ準備) の「実行タイミング」の初出で、出力ファイル群を生成 1〜4 の 4 つの派生データと書く。
4. [FR-017](../20_SRS.md#fr-017-n03-行政区域前処理データ準備) のフォールバックの括弧に、No.16 の [FR-016](../20_SRS.md#fr-016-ピーク域ポリゴン生成) は呼び出し元の [FR-004](../20_SRS.md#fr-004-33メッシュ結合解析オーケストレーション) が先に止まることを添える。
5. [FR-023](../20_SRS.md#fr-023-解析パイプライン制御) の入力の表は、転送先のデフォルトを書かず、各 FR の入力の表に任せる。

要求の中身と範囲は変えない。

## Alternatives

- **(a) 1 を、入力の表から読めるとして直さない**: 入力の表は標高タイル取得完了記録を「必須（フェーズ2〜フェーズ4 を実行するとき）」とするので、通しでも要ることは表から読める。ただし、説明と異常系だけを読むと、通しの実行に前提の検査が無いようにも読める。
- **(b) 5 で FR ごとのデフォルトを並べて書く**: 詳しくはなるが、各 FR の入力の表と同じことを 2 か所に書くことになり、片方を直したときにずれる。

## Consequences

- SRS の [FR-016](../20_SRS.md#fr-016-ピーク域ポリゴン生成)・[FR-017](../20_SRS.md#fr-017-n03-行政区域前処理データ準備)・[FR-023](../20_SRS.md#fr-023-解析パイプライン制御) を直した。ツールの振る舞いは変わらない。
- 1 は HLD 4.23 の表の中身と同じで、HLD を直す必要は無い。
