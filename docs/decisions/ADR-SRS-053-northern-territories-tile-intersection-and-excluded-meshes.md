# ADR-SRS-053: 北方領土除外タイルの交差判定と除外メッシュの扱い

| 状態 | 採用・未実装 |
| 決定日 | 2026-09-23 |

## Context

[ADR-SRS-018](ADR-SRS-018-northern-territories-skip-at-tile-fetch.md) は、北方領土除外タイルリストをタイル中心点がポリゴン内に含まれるかどうかで列挙する方式を採用した。実測調査（[research](research/northern-territories-tile-exclusion-survey.md)）により、この中心点判定では海岸線付近のタイル（中心が海側にずれるタイル）が除外から漏れることが分かった。中心点判定の除外は Z15 で 6,502 枚だが、ADR-URD-005 の交差ベースの検証では 7,321 枚とされており、約 819 枚が漏れている。

さらに、地理院の配信状況を抜き取り確認したところ、漏れた択捉島の DEM10b 海岸タイルが HTTP 200 で配信され、陸地の標高値（最高 121.78m）を含んでいることを確認した。ADR-SRS-018 が記録する「択捉島・色丹島の DEM10b は HTTP 404」（2026-06-28 時点）は、2026-09-23 時点の状態と一致しない。

除外の判定をタイル中心点から矩形の交差へ改めると、より正確に北方領土のタイルを除外できる。しかし、この判定に切り替えると、陸地が北方領土のみのメッシュ（[FR-004](../20_SRS.md#fr-004-33メッシュ結合解析オーケストレーション) の解析対象となる 1次メッシュのうち、6646・6647・6747・6748・6847・6848 の 6 メッシュ。件数・コードは N03-20260101 時点の例示）では、取得できる陸地タイルが 0 になる。[FR-004](../20_SRS.md#fr-004-33メッシュ結合解析オーケストレーション) は「対象メッシュのローカルキャッシュタイルが 1 枚も存在しない場合、エラーを出力して処理を中止する」ため、このままでは全国処理がこれらのメッシュで停止する。この停止は、周辺メッシュ（6545・6546・6645。知床・羅臼・根室・歯舞を含む）の 3×3 窓・広域窓にも波及する。

[ADR-SRS-052](ADR-SRS-052-detection-completeness-acceptance.md) は、「北方領土のタイル取得除外と、入力タイル全欠如時の停止条件の整合」を SRS の残件として挙げている。findsummits#96 の決着条件は次の 3 点である。

1. 除外リスト・対象メッシュ・取得対象タイルの対応を確認し、全欠如となる条件と隣接解析への影響を特定する。
2. 意図的除外・未整備・取得失敗を区別し、対象集合、解析/省略の状態、停止条件、完了証跡を SRS/ADR に記録する。
3. [FR-004](../20_SRS.md#fr-004-33メッシュ結合解析オーケストレーション)/[FR-014](../20_SRS.md#fr-014-広域結合解析オーケストレーション)/[FR-023](../20_SRS.md#fr-023-解析パイプライン制御) と全国受入条件を整合させ、非除外の本土を誤って省略しない正常/異常ケースを ST に追加する。

本 ADR はこの 3 点を決着させる。

## Decision

### 1. 除外タイルリストの判定方法を交差判定に改める

[FR-017](../20_SRS.md#fr-017-n03-行政区域前処理データ準備) 生成 3 の北方領土除外タイルリストは、Z15 のタイル矩形が N03_007 01695〜01700 のポリゴンと交差するタイルをすべて列挙する（従来の「タイル中心点がポリゴン内」から変更）。DEM10b（Z14）は従来どおり Z15 の各エントリを `(x // 2, y // 2)` に変換して導出する。

### 2. 北方領土除外メッシュリストを新設する（FR-017 生成 4）

日本全土1次メッシュコードリストのうち、メッシュ範囲（四隅の緯度経度による矩形）が北方領土 6 村のポリゴンと交差し、かつ北方領土 6 村以外の N03 ポリゴンのいずれとも交差しないメッシュを列挙する。N03 の版と日本全土1次メッシュコードリストだけで決まり、地理院の配信状況には依存しない。

### 3. 除外メッシュは全工程でリスト外メッシュと同じに扱う

- [FR-001](../20_SRS.md#fr-001-標高タイル事前取得): 除外タイルは取得しない。除外メッシュは取得対象メッシュから外し、そのメッシュの取得範囲のタイルを取得しない（隣接メッシュの範囲にも含まれる境界タイルは、隣接メッシュ側で取得する）。旧方式で取得済みの除外タイル・除外メッシュ範囲のタイルがローカルキャッシュにあれば削除する（既存の HTTP 404 時削除と同じ位置で行う）。これは、エンジンが「ローカルキャッシュにあるタイルはすべて解析対象」とする前提（ADR-SRS-018 の Decision (b)）の下で、旧方式で取得済みの海岸タイルが残っていると北方領土のピークが解析に混入するためである。
- [FR-004](../20_SRS.md#fr-004-33メッシュ結合解析オーケストレーション)・[FR-014](../20_SRS.md#fr-014-広域結合解析オーケストレーション): 除外メッシュは解析対象メッシュにしない（解析中心にせず、bounding box にも含めない）。3×3・広域の窓内に除外メッシュが含まれる場合は、リスト外メッシュと同じく NODATA 充填して続行する。除外メッシュを省略したことは実行ログに記録する。除外メッシュ以外の存在メッシュは、未整備によるタイル全欠如を含め、従来どおりタイルが 1 枚も無ければエラー終了する（意図的除外と未整備・取得失敗を区別する）。
- [FR-008](../20_SRS.md#fr-008-per-mesh-csv-統合): `expected_count` の周辺メッシュ数に除外メッシュを数えない。除外メッシュは解析対象メッシュではないため、[FR-007](../20_SRS.md#fr-007-per-mesh-csv-出力プロミネンス閾値適用) の範囲フィルタにより、除外メッシュに所属するピークは出力されない（不変条件）。
- [FR-023](../20_SRS.md#fr-023-解析パイプライン制御): 変更しない。[FR-023](../20_SRS.md#fr-023-解析パイプライン制御) は日本全土1次メッシュコードリストを直接読まない方針のため、除外メッシュリストも直接読まない。利用者指定の1次メッシュコードリストに除外メッシュが含まれる場合の警告・スキップは、リスト外コードの警告と同じ位置（[FR-001](../20_SRS.md#fr-001-標高タイル事前取得)・[FR-004](../20_SRS.md#fr-004-33メッシュ結合解析オーケストレーション)）で行う。

### 4. 全国完了判定を改める

[NFR-001](../20_SRS.md#nfr-001-精度検出網羅性) の全国処理範囲は、期待集合 175 を維持する。完了は次の 3 条件で判定する。

1. 正常完了集合 ∪ 省略集合（独立導出・事前固定した除外メッシュ集合） = 期待集合
2. 正常完了集合 ∩ 省略集合 = ∅
3. 製品が実行ログに残す省略集合 = 独立導出した省略集合

北方領土と本土の両方を含むメッシュ（6545・6546・6645 等）は省略しない。取得失敗・異常終了で対象集合を減らさない既存の規則は維持する。

## Alternatives

**(A) 除外メッシュを日本全土1次メッシュコードリストから削除する（竹島と同じ方式）**

却下。URD 4 章の [UR-001](../10_URD.md#ur-001) と 5 章は 175 メッシュを解析対象とし、6747 等を含むと明記している。この方式では URD および 175 の件数を参照する SRS・ST 等の文書群すべての改訂が必要になる。加えて、[NFR-001](../20_SRS.md#nfr-001-精度検出網羅性) はすでに「竹島のメッシュ単位除外と北方領土のタイル単位除外を区別し、欠損入力や異常終了で対象集合を減らさない」と定めており、この方式は既存の決定と矛盾する。

**(B) タイル除外はそのまま、検出後のピーク位置で北方領土かどうかを後段判定する**

却下。ADR-URD-005 の Alternatives がすでに、後段（[FR-009](../20_SRS.md#fr-009-sotaリスト突合match_status-判定)）でのポストフィルタは検出段階が遅すぎるとして却下している。加えて、この方式は除外メッシュの全欠如による停止という問題を解決しない。

**(C) 中心点判定のまま据え置く**

却下。地理院の配信状況が変われば、北方領土の海岸断片が解析に混入する可能性が残る。目的「地理院の配信状況に依存しない」を満たさない。

## Consequences

- [FR-017](../20_SRS.md#fr-017-n03-行政区域前処理データ準備) の出力が 3 種から 4 種になり、入力に日本全土1次メッシュコードリストが加わる。
- [FR-004](../20_SRS.md#fr-004-33メッシュ結合解析オーケストレーション)・[FR-014](../20_SRS.md#fr-014-広域結合解析オーケストレーション)（地形解析エンジン）が、北方領土除外メッシュリストという業務規則由来の入力を持つ。ADR-SRS-018 の Decision (b) の採用理由は「業務ルールをエンジンに埋め込まない」ことだったが、エンジンが扱うのは「リスト外メッシュと同じ扱いのメッシュ集合」に過ぎず、北方領土の判定そのものは [FR-017](../20_SRS.md#fr-017-n03-行政区域前処理データ準備) に残る。
- 旧方式（中心点判定）で生成済みの [FR-017](../20_SRS.md#fr-017-n03-行政区域前処理データ準備) の出力群と、旧方式で取得済みのローカルキャッシュは、本 ADR の適用時に削除して再生成・再取得する必要がある（操作の詳細は HLD で定める）。[FR-017](../20_SRS.md#fr-017-n03-行政区域前処理データ準備) の実行タイミングに、日本全土1次メッシュコードリストを更新したときも出力群を削除して再実行することを加える。
- 実装は HLD/LLD 確定後に行う。
