## 1. 目的・スコープ

本書はシステムテスト（ST）レベルのテストケースを定める。[ADR-ST-001](decisions/ADR-ST-001-two-part-st-no-separate-at-family.md) の方針に従い、以下の2部構成とする。

- **第1部**: [`20_SRS.md`](20_SRS.md) のFR/NFR単位のシステムテストケース（ソフトウェア要件仕様書（SRS）の検証）
- **第2部**: [`10_URD.md`](10_URD.md) のUR単位の妥当性確認シナリオ（ユーザー要件定義書（URD）の妥当性確認）。FRに一意に分解できるURは第1部のテストケースへの参照とし、FR横断・分解不能なURのみ専用シナリオを記述する

テストレベル定義・自動/手動の分担・テスト環境・開始基準・合否判定基準・カバレッジ粒度の方針は [`02_test_policy.md`](02_test_policy.md) を正本とし、本書では重複記述しない。

## 2. テストケース記述規約

- **テストケースID命名規則**: [`02_test_policy.md` §6](02_test_policy.md#6-テストケースid命名の大枠) の共通規則に従う。第1部は `ST-FR-<番号>-<連番>` / `ST-NFR-<番号>-<連番>`、第2部は `ST-UR-<番号>-<連番>`
- **記述テンプレート**: 各テストケースは以下を記述する。
  - **前提条件**: テスト実行前に満たすべき状態（入力データ・環境等）
  - **手順**: 実行する操作・コマンド
  - **期待結果**: 正しい場合に得られるべき出力・状態
  - **合否判定基準**: 期待結果との照合方法
- **カバレッジ粒度**: [`02_test_policy.md` §5.2](02_test_policy.md#52-カバレッジ粒度の正本) の既定方針に従い、リスクの高いFR/NFRは複数ケース、その他は代表ケース1件とする
- **期待値の記録**: 各ケースの期待結果は、前提に書いた入力から SRS に従って導き、実行前に記録する。製品の出力から写さない（[テスト方針書 §3.3](02_test_policy.md#33-期待値の根拠)）。
- **結果の記録**: 各ケースの結果は[テスト方針書 §5.5](02_test_policy.md#55-テスト結果の記録) の項目で記録する。未実施・未完了（本書の [§3.8.2](#382-検出網羅性の基準セットと判定手順) と `ST-UR-008-01` の用語）は[テスト方針書 §5.4](02_test_policy.md#54-未実施ケースの扱い) に従う。
- **UT/IT で実施するケース**: 作った地形・画素値を入力とする次のケースは、[テスト方針書 §3.3](02_test_policy.md#33-期待値の根拠) に従い単体テスト（UT）・結合テスト（IT）で実施する: [FR-002](20_SRS.md#fr-002-dem-階層フォールバック)・[FR-003](20_SRS.md#fr-003-標高デコードnodata-処理)・[FR-005](20_SRS.md#fr-005-ピーク候補検出)・[FR-006](20_SRS.md#fr-006-コル検出プロミネンス計算) の全ケース、`ST-FR-007-02`・`ST-FR-007-05`・`ST-FR-007-06`・`ST-FR-007-07`・`ST-FR-007-08`・`ST-FR-007-09`・`ST-FR-014-05`・`ST-FR-014-06`・`ST-FR-014-18`・`ST-FR-015-04`・`ST-FR-015-05`・`ST-FR-015-06`・`ST-FR-015-07`・`ST-FR-016-03`・`ST-FR-016-04`・`ST-FR-016-05`・`ST-FR-016-06`・`ST-FR-016-07`。製品が書いたファイルを、製品が読み戻す前に差し替えないと起こせない `ST-FR-014-17` も、同じく UT・IT で実施する。`50_UT.md`・`60_IT.md` の作成時に移し、ST では移した先のケースの結果を参照して合否を記録する。ST での地形の確認は[検出網羅性の基準セット](#382-検出網羅性の基準セットと判定手順)が担う。
- **申請系の共通試験データ**: 申請系のケースは、固定入力 `FX-APP` と期待値表 `EXP-APP` を共通に使う。前提が `FX-APP` を指すケースは、生成物を `EXP-APP` の該当行と自動照合して合否を決める（[テスト方針書 §3.1](02_test_policy.md#31-自動テストと手動確認の役割分担)）。前提に差分操作を書いたケースは、`FX-APP` にその操作を加えた状態を入力とし、操作後の期待値も `EXP-APP` に記録する。
  - `FX-APP-B`（バッチ入力）: [FR-009](20_SRS.md#fr-009-sotaリスト突合match_status-判定) の入力一式（`merged_peak.csv`・`merged_peak.geojson`・SOTA サミットリスト CSV・SOTA 既存サミット GeoJSON・N03 前処理済み地域/市区町村 GeoJSON・標高タイル（ローカルキャッシュ）3 枚。3 枚は既知の異なる mtime を持ち、`$DATA_DIR/tiles/` にはこの 3 枚のみが存在する）。次を作れる内容にする: new ピーク P1、dominant ピーク P2 とそれに従属する通常 delete 2 件、dominant ピーク P3 とそれに従属する通常 delete 1 件、band_change の matched ピーク 1 件（`peak_elev` 1099.99m・登録 1100m）、no_change の matched ピーク 2 件（`peak_elev` 1100.00m・登録 1100m と、`peak_elev` 1050m・登録 1099m）、band_change の matched ピークを主ピークとする通常 delete 1 件、複数登録の保留組 2 組（組 A: AZ 内 2 件と AZ 外保留 1 件、組 B: AZ 内 2 件）、孤立 unmatched 2 件（U1・U2。U1 は SOTA 既存サミット GeoJSON に日本語山岳名が無く、`summit_name_jp` が空文字になる）。全ピークは `key_col_resolved=true` で、不備ゲートに掛からない。
  - `FX-APP-V`（ビューア状態）: P1 に山岳名JP「試験山一」・山岳名EN「Shiken-yama Ichi」、P2 に山岳名JP「試験山二」（EN は空）、P3 に山岳名JP「試験山三」（EN は空）を入力。U1 を担当者指定削除にして根拠「試験用根拠」を入力（U2 は未選択）。P3 を理由「試験用除外」で申請から除外（manual。P3 に従属する delete は parent_add になる）。
  - `EXP-APP`: `FX-APP-B` から [FR-009](20_SRS.md#fr-009-sotaリスト突合match_status-判定) が作る中心データの各フィーチャ（`category`・`match_status`・`points`・`sota_points`・`is_band_change_candidate`・`rationale`）、`metadata`（`gsi_tile_latest_date` はタイル 3 枚の mtime 最大値、`attribution`・`source_url`・`license_url` は SRS の固定値）、`FX-APP-V` を反映した申請書の出力行と A〜J 列、両サミット一覧の行と各列（`merged_summit_revised.xlsx` の「出典」シートを含む）、5 GeoJSON のフィーチャ構成、エクスポート時の警告（保留組数・保留登録件数・除外件数・根拠未記入件数・山岳名JP 未入力件数）。差分操作のあるケースは、その操作後の同じ項目。
  - `FX-APP` と `EXP-APP` は ST 実行前に作成し、内容をコミット ID または内容ハッシュで固定する。未作成なら参照ケースは未実施として記録する（[テスト方針書 §5.4](02_test_policy.md#54-未実施ケースの扱い)）。

（省略集合の導出に用いる N03 の版は、製品が使用した版と同一に固定する）。
[ADR-URD-009](decisions/ADR-URD-009-takeshima-exclusion.md) のメッシュ5531除外と、

①製品の対象リストと期待集合、②（正常完了集合 ∪ 省略集合）と期待集合を別々に照合し、重複・欠落を確認する。
正常完了集合と省略集合が重ならないこと（∩ = ∅）、製品が実行ログに残す省略集合が独立導出した省略集合と一致することも確認する。
各メッシュの完了ログと当該実行の per-mesh 成果物を対応付ける。省略集合に属するメッシュは per-mesh 成果物の代わりに省略ログで対応付ける。

過去の出力だけで完了したことにしない。入力タイルの欠如や異常終了（未整備による全欠如を含む）は別途記録し、対象メッシュを分母から消さない。

| セット識別 | 版、作成/承認日、メンテナの承認、事前固定した内容のコミット ID または内容ハッシュ、対応 SRS 版、入力 DEM の取得情報と内容識別情報、期待メッシュ集合、省略集合とその導出に用いた N03 の版、設定（一次/最終フィルタ閾値を含む） |
| ピーク識別 | セット内で不変の ID、名称、地域、SOTA コードは存在する場合の参照情報。コードが異なるだけの同一地形は重複して数えない |
| 検出位置 | WGS84 の基準位置、出力ピーク座標の許容領域または許容座標集合、その根拠。同標高頂部や採用 DEM の解像度も考慮する |
| 期待する適格性 | ピークと Key コルの確認根拠、150m以上と判断した根拠、採用 DEM の種別/状態、対象区分、確認者 |
| 判定状態 | 必須、候補保留、対象外。保留/対象外には理由と根拠を記録する。必須セットとは分けて管理する |
| 履歴 | 追加・変更・対象外化の理由、対応した検出漏れ、再評価した入力版、承認記録 |

##### 正解を独立に確かめる

SOTA リスト、既存研究で扱った著名独立峰・陸地最高峰、未登録ピーク、既知の欠陥を候補源にする。
その候補が採用 DEM と仕様の閾値に適合することを、地形図・DEM の独立確認や検証対象とは独立した計算で裏付ける。
本製品のどの版・どの実行の出力も、候補位置の当たりを付ける用途にのみ使い、
適格性・許容位置・ピーク/Key コル・150m以上という正解の根拠にしない。
現行登録されているという理由だけで150m以上とみなすこともしない。
既存の親ピーク距離の代理調査は選定の手掛かりにとどめ、真の Key コルの位置・標高を確定する正解として流用しない。
陸地最高峰の手動リストは処理入力であり、そのリストに載っていること自体を適格性の独立証拠にしない。

DEM の誤差や欠損等で適格性が確定できない候補は保留とし、必須セットへ無理に入れない。
適格性を確認済みの峰に対する製品側の解析限界（広域解析の上限でもコルを解決できない等）は保留・対象外化の理由にしない。
ただし結果を見て必須から保留に移して同じ実行を合格にしない。必要区分の代替を含め、改版と再承認を要する。
実世界の地形と DEM 上の期待結果に差がある場合も、差と根拠を残す。誤差幅を一律に仮定して対象を除外しない。

##### 同一ピークの照合

各必須レコードの許容位置は、別の適格ピークを同じ山として拾わない大きさ・形に事前確定する。
一律の大きな距離半径や実行結果を見た領域拡張を使わず、座標の数値完全一致だけにも依存しない。
実際の許容値と単位・境界を含むかどうかは各レコードに必須とし、数値未確定のまま試験を始めない。

全必須レコードと最終出力行を一括照合し、各レコードに該当する行がちょうど1件で、
その行が他の必須レコードへ重複割当されない場合に一意とする。
0件は未検出、複数件や重複割当は曖昧とし、いずれも検出成功へ数えない。
曖昧な場合は基準の不備か出力の不備かを切り分けるが、解消前には合格を出さない。
近接した2峰、同標高頂部、メッシュ境界の例で誤照合・取り違えがないことも確認する。
基準外の余分な行を本再現率の分子に加えない。基準外だから偽陽性と断定することもしない。

##### 代表性と境界条件

実データの必須セットは以下の区分をすべて満たす。一つのレコードが複数区分を満たしてよい。
区分ごとの選定理由・件数・該当 ID を選定表に残す。件数は統計的な全国保証のサンプルサイズを意味しない。

| 区分 | 最低限の対象 |
|---|---|
| 地理的な広がり | 北海道・本州・四国・九州・それら以外の島嶼にそれぞれ1件以上 |
| 登録との独立性 | 現行 SOTA 登録のある適格ピークと、登録のない適格ピークをそれぞれ1件以上 |
| 解析窓と独立峰 | 通常解析で確定するものと、通常解析の窓外に Key コルがあり広域解析を必要とするものをそれぞれ1件以上 |
| 海面確定 | 自動で海面コルを確定する島の最高峰1件以上、および採用時の陸地最高峰リストの全対象 |
| DEM の違い | 基準ピーク画素または陸上 Key コル画素で DEM5 を採用する対象と、DEM10b フォールバックを採用する対象をそれぞれ1件以上。採用種別は下記のキャッシュ画素の証拠で確定する |
| 境界と近接 | タイル境界付近、1次メッシュ境界付近をそれぞれ1件以上。近接しているが別々に150m以上を満たす2峰を1組以上 |
| 既知の漏れ | これまでに確認して修正した検出漏れがあればすべて維持。事例がない場合だけ該当なしの根拠を残して空を許容し、空の必須区分による不合格の対象外とする。同一原因の代表化は根拠と承認を記録した改版でのみ行う |

DEM 区分の証拠は、固定した入力キャッシュの対象画素について、各候補種別のタイル ID・内容ハッシュ・
画素位置・存在/NODATA/有効値と、[FR-002](20_SRS.md#fr-002-dem-階層フォールバック) の優先順位に従った採用種別を記録する。
DEM5 と DEM10b の画素対応・解析グリッドも明示する。海面コルは実在画素として扱わず、ピーク画素を使う。
この区分は記録した画素での採用を意味し、山域全体が同じ DEM 種別であるとは主張しない。
製品の CSV に DEM 種別列の追加を要求せず、試験側で入力から確認する。
境界付近の定義（対象境界、距離/画素数・単位・境界の包含と根拠）は各レコードへ事前記録する。

候補例は [UR-007](10_URD.md#ur-007) の大山・東北の孤立峰や、
[ADR-SRS-019](decisions/ADR-SRS-019-land-summit-highest-peak-handling.md) の陸地最高峰である。
例示は期待値の確定を意味しない。SOTA コード・位置・コル・解析段階の期待値はセット作成時に一次データで確認する。
過去の研究資料の古い件数や代理距離から、特定の広域段階で必ず確定するとは決めない。

実データで正解を固定しにくい境界は、既知の地形を作った試験入力でも確認する。
150mちょうど、直下、直上、同標高頂部、近接2峰、境界を跨ぐピーク、窓外コルによる未確定保持から広域確定を対象とする。
地形の期待値は手計算等の独立した根拠を残し、UT/IT/ST の担当は [テスト方針書](02_test_policy.md) に従う。
この補助確認で全国実データの基準セットや処理範囲確認を置き換えない。150m直下の不採用は既存の閾値要件の検証であり、
本再現率の分母は150m以上の必須ピークに限る。

##### 基準の保守と再評価

初回セットは ST 実行前にメンテナが根拠・必須区分・照合条件を確認して版を確定する。
独立性は人数や役割でなく、正解の根拠が本製品のいずれの版の出力にも由来しないことを示す記録で担保する。
一人で作成・承認する場合も根拠資料と確認過程を残す。
基準レコード・期待メッシュ集合・選定表・根拠・許容位置を含む内容一式を、試験開始前にコミット ID または内容ハッシュで固定する。
ケースの開始記録（[テスト方針書 5.5](02_test_policy.md#55-テスト結果の記録)）にその識別子と入力版・コード版・設定を残し、終了時に同じ内容で照合したことを確認する。承認記録とケースの開始記録も保存する。
改版時に識別子を使い回さない。単に実行後にハッシュを作っただけのものは事前確定の証拠にしない。
DEM/SOTA 参照版や解析規則・陸地最高峰リストの変更、新たな漏れの発見、照合の曖昧さを改版のトリガーとする。
SOTA リスト更新だけで地形上の必須ピークを消さず、地形・入力・仕様上の適格性を確認する。
不変の ID と旧版を保存し、削除や領域変更には独立した根拠とメンテナ承認を残す。

合格報告は入力版・基準版と事前固定識別子・対象コード版・設定・範囲照合結果・各基準の照合先・漏れ/曖昧/未確定の内訳を含める。
基準を変更した場合は旧版での結果も残し、新版で再実行/再照合した結果を別に示す。
再照合で保存済みの出力を使う場合も、新版の事前固定とケースの開始記録を作り、元の解析の版・入力が新版と適合することを確認する。
そのケースの開始記録には照合対象の保存済み出力の内容ハッシュも残し、照合終了時に同じ内容であることを確認する。
解析のコード・入力・設定が変わる場合は解析を再実行する。再照合による合格を、解析前から新版を固定していた試験と混同しない。
基準に正当な訂正が必要でも、前の失敗をなかったことにしない。
既知の必須ピークの漏れは本基準の不合格であり、既知欠陥の登録だけで合格に読み替えない。
リリース可否の例外判断が別にある場合も、本基準の測定値・判定はそのまま報告する。
[テスト方針書 §5.3](02_test_policy.md#53-既知欠陥の許容基準) による既知欠陥の許容判断は別に記録し、本基準の漏れ数や不合格を合格へ書き換えない。

##### 合否判定の対照例

| 例 | 期待する判定 |
|---|---|
| 175件の完了ログだが1コード重複・別の1コード欠落 | 全国処理範囲が不一致で不合格 |
| 北方領土除外メッシュを正常完了集合に含めた（除外メッシュが解析中心として実行された） | 意図的除外と正常完了の混同で不合格 |
| 本土を含むメッシュ（例: 知床・羅臼・根室を含むメッシュ）を省略集合に含めた | 誤省略で不合格。北方領土除外は「含有メッシュ全体の削除」ではない |
| 必須100件中99件を検出、1件だけ消失 | 再現率99%、漏れ1件で不合格 |
| 必須全件の位置があるが、1件のコルが未確定 | そのレコードは成功に数えず不合格 |
| 必須レコードの許容位置に出力行が2件、または1件だが最終閾値未満 | 前者は曖昧、後者は適格性不一致で、いずれも成功に数えず不合格 |
| 近接する2基準ピークに同じ出力行を割当 | 重複割当で不合格。別の2峰を検出したことにしない |
| 必須全件が一意に確定、広域代表の stability が `-` | stability だけを理由に不合格にしない。範囲と他条件も成立すれば合格 |
| 再現率100%だが島嶼区分に必須レコードがない | 基準セットの必須区分不足で合格にしない |
| 必須レコード0件、または許容位置の数値が未確定 | 基準妥当性を満たさず合格にしない。0/0 を100%としない |
| 出力を見て許容半径を広げる、未検出を対象外へ移す | 同じ基準での合格にしない。独立根拠・改版・再承認・再評価が必要 |
| 必須全件検出だが、新しい基準外の漏れが確認された | 未知の漏れゼロを主張せず、欠陥として処置し回帰基準へ追加 |

| ZIP | 展開でき、SRS の全構成物が揃う。各 GeoJSON は FeatureCollection として読め、metadata が今回の突合済み GeoJSON から複製されている |
| PNG | 当該解析の出力先に自動生成され、画像として開け、対象範囲の地形が表示される |
| 除外判断 JSON | JSON として読め、明示的な読込・確認操作で保存時と同じ台帳内容を復元できる |

ZIP の構成は [SRS §6.2.8](20_SRS.md#628-申請エビデンス-zipパッケージング仕様) を正とし、除外判断 JSON は同梱しない。
申請行・各分類フィーチャ・除外判断 records は仕様どおり0件でもよく、非空の除外候補を要求しない。
各 I/F の全項目/全行の正しさ・数値精度・検出網羅性は第1部の対応ケースと対応 UR のシナリオへ委ねる。
公開用ビューアの配信は [FR-020](20_SRS.md#fr-020-公開用ビューア配信) の検証で扱い、公式提出とともに本シナリオの終点に含めない。

文書にない補足が必要なら文書不備とする。外部サービス停止や入力品質による正当な不備ゲート発動は未完了と原因を記録し、文書/機能不備と区別する。
仕様上許容する警告・要確認だけで生成失敗とはしない。根拠付き設定見直しは [SRS §2.2.1](20_SRS.md#221-設定可能項目) に従い、是正後の設定と再実行結果を残す。
文書修正・入力是正後は本確認の記載手順で取得したキャッシュ等を再利用できる。取得履歴と使用段階を残し、未変更の準備段階の証跡と再実行を合わせて判定する。
記載手順では作れないキャッシュの持込や過去の出力の流用を、今回の成果物生成の成功として扱わない。
