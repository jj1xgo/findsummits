## 1. 目的・スコープ

本書は結合テスト（IT）のテストケースを定める。つなぎ目の一覧と ID の正本は、概要設計書（HLD）の [3 章](30_HLD.md#3-プログラム構造)の各節の「結合のつなぎ目」である。第 1 部に内部結合、第 2 部に外部結合を置き、内部結合を先に確かめる（[テスト方針書 §2](02_test_policy.md#2-テストレベル定義と役割分担)）。

テストレベル定義・開始基準・合否判定基準・カバレッジの粒度・結果の記録は、[`02_test_policy.md`](02_test_policy.md) を正本とし、本書では重複して書かない。関数の中の挙動は単体テスト（UT）で、システムの外へ出す成果物の中身はシステムテスト仕様書（ST）で確かめる。期待値の根拠は、HLD とソフトウェア要件仕様書（SRS）である。本書の形の決定は [ADR-IT-001](decisions/ADR-IT-001-two-part-it-and-moved-st-cases.md) にある。

## 2. テストケース記述規約

- **テストケースID命名規則**: [テスト方針書 §6](02_test_policy.md#6-テストケースid命名の大枠) の共通規則に従い、`IT-<つなぎ目の ID>-<連番>` とする（`IT-CMP5-INT1-01`、`IT-CMP5-EXT1-01`）。連番は、つなぎ目ごとに `01` から振る。手動で行うケースは、ID の直後に `（手動）` を付ける。
- **記述テンプレート**: 各テストケースは、前提条件・手順・期待結果・合否判定基準を書く（[`70_ST.md`](70_ST.md) の §2 と同じ 4 列）。
- **カバレッジ粒度**: [テスト方針書 §5.2](02_test_policy.md#52-カバレッジ粒度の正本) の IT の段落に従う。
- **期待値の記録**: 各ケースの期待結果は、前提に書いた入力から HLD と SRS に従って導き、実行の前に記録する。製品の出力から写さない（[テスト方針書 §3.3](02_test_policy.md#33-期待値の根拠)）。
- **結果の記録**: 各ケースの結果は[テスト方針書 §5.5](02_test_policy.md#55-テスト結果の記録) の項目で記録する。
- **システムの外の相手**: 国土地理院のタイルサーバーは、実サーバーから少数のタイルを取って確かめ、応答ごとの扱いは応答を制御できる模擬サーバーで確かめる（[テスト方針書 §3.2](02_test_policy.md#32-実データ依存の扱い)）。CDN・背景タイルの提供元からの取得も、実サービスから少数を取得し、応答ごとの扱いは応答を差し替えた試験で確かめる。静的ホスティングの組み立て（Workers Builds）は、実際の push で起きた組み立てと配信を観察して手動で記録し、IT のために push はしない。
- **起動の範囲**: `run_pipeline` の通しの実行と `--phase 2` は、ケースに `--mesh` を書いていないものも、試験用の地形を置いたメッシュだけに `--mesh` で絞る。`--mesh` なしの通しと `--phase 3`・`--phase 4` は、日本全土の取得完了の記録を起動前提条件にする（[HLD 4.23.2](30_HLD.md#4232-処理の流れ)）ので、記録は `FX-IT-REC` で用意する。広域の解析は対象ピークの組のメッシュだけを解析するので、全国の解析にはならない。内部の起動口を直接起動する手順は、CMP3（パイプライン制御）が渡すのと同じ引数（`--config <絶対パス>` を含む。[HLD 2.4.5](30_HLD.md#245-内部引数)）で起動する。
- **共有の試験入力**: 複数のケースで使う試験入力は `FX-IT-<名前>` と名前を付け、本節に中身を書く。1 つのケースだけで使う入力は、そのケースの前提条件に書く。
  - `FX-IT-N03`: 配布されている N03 行政区域 ZIP と同じ書式（ZIP の最上位に市区町村単位の `N03-<YYYYMMDD>.geojson` を持つ）で、HLD の [4.17.2](30_HLD.md#4172-処理の流れ) の「地域と SOTA のコード」の表の 60 地域のそれぞれに市区町村のポリゴンを 1 つ以上と、根室振興局の北方領土 6 村（01695〜01700）を含み、同じ節の「入力の検証」に当たらない最小の試験用の ZIP。名前は `N03-20250101_GML.zip`。
  - `FX-IT-REC`: 日本全土1次メッシュコードリストから北方領土除外メッシュを除いたすべてのコードを、1 行 1 件で書いた取得完了の記録（`tiles/` の直下）。CMP2（タイル取得）との受け渡しを確かめるケース（`CMP2-INT1`・`CMP3-EXT1`）と、記録を消したり壊したりするケースのほかは、これで記録を用意する。
  - `FX-IT-GSI`: 応答を制御できる模擬タイルサーバー。要求ごとに URL・`If-Modified-Since`・User-Agent・受けた時刻・応答を返し終えた時刻（切断したときは切った時刻）を記録し、タイルごとに 200（`Last-Modified` の有無を選べる）・301・304・403・404・429・500・502・503 の応答と、`Retry-After`、応答の遅れ、応答しないこと（タイムアウト）、切断を返せる。CMP2（タイル取得）の `fetch_tiles` と、CMP7（申請書生成 UI）・CMP8（公開用ビューア）のブラウザの取得先をこのサーバーへ向ける方法は、テストの枠組みを選ぶとき（[テスト方針書 §3.4](02_test_policy.md#34-テストを先に書く進め方)）に決める。`fetch_tiles` の再試行と待ちのケース（`CMP2-EXT2`）は、`FX-IT-GSI` を `fetch_tiles` と同じ計算機で動かし、時刻の照合に許容幅 ε（1 秒。通信と処理の遅れがこれより十分に短いことを、正式な実行の前に確かめて記録する）を使う。待ち時間は、応答を返し終えてから次の要求を受けるまでを、待ち時間 W について W − ε 以上 W + ε 未満で照らす。異常な応答を受けた後の新しい要求の有無を照らすケースは、最大並列数を 2 にし、もう一方のワーカーの要求を受けて応答を止めておいてから異常な応答を返す（返す時点で、実行中の要求がすべてサーバーに届いているので、その後に受けた要求は新しい要求である）。止めておいた応答は、異常な応答を返し終えてから ε より後、30 秒（タイムアウト）より前に返す。

## 3. 第1部: 内部結合

内部結合は、1 つのコンポーネントの中のプログラムどうし（同じプログラムの別の起動どうしを含む）の受け渡しである（用語の定義は [HLD 1 章](30_HLD.md#1-用語定義)）。

### 3.4 CMP4 地形解析エンジン

#### CMP4-INT1: analyze_terrain（前の起動）→ analyze_terrain（広域モード）

- **つなぎ目**: [3.4.5](30_HLD.md#345-結合のつなぎ目)

省略の判定は [4.14.2](30_HLD.md#4142-処理の流れ) の 4「対象メッシュごとに、昇順に次を行う」の 2 の 3（読む `.meshset` の選び方と、含まれれば省略すること）。どのケースも、広域モード（N）の起動に、対象メッシュ M の 1 件の対象ピークを持つ N−1 のリスト（N=4 なら `key_col_unresolved_peaks-3.csv`、N=5 なら `key_col_unresolved_peaks-4.csv`）を渡す。対象ピークは、どのパターンでも確定しない地形に置く（対象ピークがすべて確定すると残りのパターンを行わないので、確かめるパターンに届かなくなる。同じ節の 4 の 2 の 10「早期終了を判定する」）。前提に挙げた `.meshset` のほかに、どのパターンの解析対象メッシュの集合も含む `.meshset` は置かず、前提に挙げた `.meshset` も、確かめるパターンのほかのパターンの集合を含まないように作る。M のまわりの存在メッシュの配置は、4 つのパターンの解析対象メッシュの集合がどれも互いに含まれないものにする（同じ起動の中で先のパターンが書いた `.meshset` が、後のパターンを省略させないため）。これで、確かめるパターンのほかは省略されずに行われる。確かめるパターンに届いたことは、そのパターンの省略か解析のログの行で照らす。
