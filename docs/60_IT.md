## 1. 目的・スコープ

本書は結合テスト（IT）のテストケースを定める。つなぎ目の一覧と ID の正本は、概要設計書（HLD）の [3 章](30_HLD.md#3-プログラム構造)の各節の「結合のつなぎ目」である。第 1 部に内部結合、第 2 部に外部結合を置き、内部結合を先に確かめる（[テスト方針書 §2](02_test_policy.md#2-テストレベル定義と役割分担)）。

テストレベル定義・開始基準・合否判定基準・カバレッジの粒度・結果の記録は、[`02_test_policy.md`](02_test_policy.md) を正本とし、本書では重複して書かない。関数の中の挙動は単体テスト（UT）で、システムの外へ出す成果物の中身はシステムテスト仕様書（ST）で確かめる。期待値の根拠は、HLD とソフトウェア要件仕様書（SRS）である。本書の形の決定は [ADR-IT-001](decisions/ADR-IT-001-two-part-it-and-moved-st-cases.md) にある。

## 2. テストケース記述規約

- **テストケースID命名規則**: [テスト方針書 §6](02_test_policy.md#6-テストケースid命名の大枠) の共通規則に従い、`IT-<つなぎ目の ID>-<連番>` とする（`IT-CMP5-INT1-01`、`IT-CMP5-EXT1-01`）。連番は、つなぎ目ごとに `01` から振る。手動で行うケースは、ID の直後に `（手動）` を付ける。
- **記述テンプレート**: 各テストケースは、前提条件・手順・期待結果・合否判定基準を書く（[`70_ST.md`](70_ST.md) の §2 と同じ 4 列）。
- **カバレッジ粒度**: [テスト方針書 §5.2](02_test_policy.md#52-カバレッジ粒度の正本) の IT の段落に従う。
- **期待値の記録**: 各ケースの期待結果は、前提に書いた入力から HLD と SRS に従って導き、実行の前に記録する。製品の出力から写さない（[テスト方針書 §3.3](02_test_policy.md#33-期待値の根拠)）。
- **結果の記録**: 各ケースの結果は[テスト方針書 §5.5](02_test_policy.md#55-テスト結果の記録) の項目で記録する。
- **システムの外の相手**: 国土地理院のタイルサーバーは、実サーバーから少数のタイルを取って確かめ、応答ごとの扱いは応答を制御できる模擬サーバーで確かめる（[テスト方針書 §3.2](02_test_policy.md#32-実データ依存の扱い)）。CDN・背景タイルの提供元からの取得も、実サービスから少数を取得し、応答ごとの扱いは応答を差し替えた試験で確かめる。静的ホスティングの組み立て（Workers Builds）は、実際の push で起きた組み立てと配信を観察して手動で記録し、IT のために push はしない。
- **共有の試験入力**: 複数のケースで使う試験入力は `FX-IT-<名前>` と名前を付け、本節に中身を書く。1 つのケースだけで使う入力は、そのケースの前提条件に書く。

## 3. 第1部: 内部結合

内部結合は、1 つのコンポーネントの中のプログラムどうし（同じプログラムの別の起動どうしを含む）の受け渡しである（用語の定義は [HLD 1 章](30_HLD.md#1-用語定義)）。

### 3.5 CMP5 統合・突合

#### CMP5-INT3: merge_peaks・merge_zones → match_summits

- **つなぎ目**: [3.5.5](30_HLD.md#355-結合のつなぎ目)

| ID | 前提条件 | 手順 | 期待結果 | 合否判定基準 |
|---|---|---|---|---|
| `IT-CMP5-INT3-01` | `IT-CMP5-EXT2-01` を実行した後の `merged_peak.csv`・`merged_peak.geojson`（ピーク P の delete判定ゾーンは、確定する窓の `area_complete=true` のもの）。SOTA サミットリスト CSV には、P の delete判定ゾーンの中で、アクティベーションゾーンの外の画素で、ほかのピークのどのゾーンにも入らない画素の座標のサミットを 1 件置く。別々の回に、(a) そのまま、(b) `merged_peak.csv` の P の代表行を広域の行にし、`col_elev` を Z15 のコルの標高より高い値（Z14 の 2×2 の最大値で作ったグリッドのコルの標高）に書き換える | `match_summits` を実行する（それぞれ） | (a)(b) とも終了コード 0。`match_summits` は `merged_peak.geojson` の P の delete判定ゾーンを、塗った閾値と `merged_peak.csv` の `col_elev` が合うかを確かめずにそのまま使い、そのサミットは `delete` で主ピークは P になる。`area_complete=false` の不備ゲートには当たらない。(b) の判定は (a) と同じ | 終了コードと、`merged_summit.geojson` のそのサミットの `match_status`・主ピーク、不備ゲートで止まらないこと、(a) と (b) の判定が同じことを照合（(b) で `col_elev` から閾値を求め直してゾーンを塗り直したり捨てたりする実装は、(a) と判定が変わる） |

## 4. 第2部: 外部結合

外部結合は、コンポーネントどうしと、コンポーネントとシステムの外との間の受け渡しである（用語の定義は [HLD 1 章](30_HLD.md#1-用語定義)）。各つなぎ目は、受け取る側のコンポーネントの節に置く。

### 4.5 CMP5 統合・突合

#### CMP5-EXT1: CMP4 → merge_peaks

- **つなぎ目**: [3.5.5](30_HLD.md#355-結合のつなぎ目)

| ID | 前提条件 | 手順 | 期待結果 | 合否判定基準 |
|---|---|---|---|---|
| `IT-CMP5-EXT1-01` | DEM10b だけで覆われた地点に独立峰があり、頂上の DEM10b の画素が Z15 の 2×2 へ同じ標高で複製される試験用のタイル。峰の Key コルは、通常解析（N=3）の窓の中で決まらず、広域の段で決まる配置にする | `run_pipeline` を通しで実行し、通常の解析の後に峰が未確定として広域の段へ回り、広域の段で確定するまで進める | CMP4（地形解析エンジン）の広域の起動は、峰を 2×2 の北西の画素の Z15 の座標で広域の per-mesh CSV に書き、その `peak_lat`・`peak_lon` は通常の per-mesh CSV の峰の行と同じになる。`merge_peaks` は 2 つの行を同じ Z15 の画素の 1 つのピークにまとめ（[4.8.2](30_HLD.md#482-処理の流れ) の 3「行を読む」）、`merged_peak.csv` に峰の行が 1 行だけ、`key_col_resolved=true` で出る | 広域の per-mesh CSV に峰の行が残り、その `peak_lat`・`peak_lon` が通常の per-mesh CSV の峰の行と一致すること、`merged_peak.csv` で峰が 1 行で `key_col_resolved=true` になることを照合 |

#### CMP5-EXT2: CMP4 → merge_zones

- **つなぎ目**: [3.5.5](30_HLD.md#355-結合のつなぎ目)

| ID | 前提条件 | 手順 | 期待結果 | 合否判定基準 |
|---|---|---|---|---|
| `IT-CMP5-EXT2-01` | ピーク P の Key コルの標高が、ちょうど `peak_elev` − delete判定ゾーン比高上限（既定値 250m。100 倍して丸めたキーが等しい）になる試験用の地形。P が確定する窓では、delete判定ゾーンがコルの標高より高い画素だけで塗られ、範囲の外の隣に触れずに完結する。P が未確定の窓では、同じキー以上の画素が塗られるのでコルを越えて高い山へつながり、完結しない | `run_pipeline` をフェーズ2 から通しで実行する | CMP4（地形解析エンジン）は、確定する窓の per-mesh ピーク候補 GeoJSON に、コルの画素を含まない P の delete判定ゾーンを `area_complete=true` で、未確定の窓の per-mesh ピーク候補 GeoJSON に、コルの画素を含む P の delete判定ゾーンを `area_complete=false` で書く。`merge_zones` は、`merged_peak.geojson` の P の delete判定ゾーンに、確定する窓のもの（`area_complete=true`）を採り、ジオメトリと `properties` を書き方を変えずに写す（[4.18.2](30_HLD.md#4182-処理の流れ) の 5「書き出す」） | 採られたゾーンの `area_complete` と、コルの画素の中心がゾーンの外であること、未確定の窓の per-mesh ピーク候補 GeoJSON のゾーンがコルの画素を含むこと、採られたゾーンの座標の書き方が確定する窓の per-mesh ピーク候補 GeoJSON と同じことを照合（確定する窓でコルと同じキーの画素まで塗る実装は、採られたゾーンがコルの画素を含むので誤りが分かる） |
